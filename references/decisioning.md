# Decisioning: Data Graphs, Personalization Points, Content Schemas, Decisions and Recommenders

## Scope
- How Salesforce Personalization (SP) turns a request into content: profile and item data graphs, personalization points, content schemas, decisions (targeting rules, merge fields), recommenders and filters, the Data 360 real-time layer SP reads, batch decisions, and limits.
- Baseline: SP Help and developer docs at release 264.0.0; 260/262 release notes supply history. Authoritative: Help `persnl_*`/`mc_persnl_*` (breadcrumb "Salesforce Help|Docs|Salesforce Personalization"), `developer/einstein-personalization`, Data 360 Help and DMO reference, release notes.
- Channels (Web SDK, WPM, mobile, email, Flow) are covered in other files; only their decisioning touchpoints appear here.
- Marketing Cloud Personalization (MCP) appears only in "MCP confusion traps". Labels: `(UNVERIFIED)` = not confirmed in docs; `(Field-observed, undocumented)` = seen in real implementations, absent from docs; "(inference)" = reasoned from the cited docs.

## 1. Profile data graphs in personalization points

### 1.1 Object chain
- Data space → profile data graph → personalization point (personalization type + content schema) → prioritized decisions (targeting rules + attribute values or a recommender) → response → Personalization Log DMO. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_real_time_profile_data_graphs.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_basics_terms.htm&release=264.0.0&type=5)
- A point is linked to exactly one data space (a data space can hold many points); its profile data graph must reside in that data space. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_considerations.htm&release=264.0.0&type=5)
- The graph gates recommenders (only those built on the same profile data graph are selectable) and targeting data points (direct attributes, related attributes, calculated insights, segment memberships). [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_considerations.htm&release=264.0.0&type=5)

### 1.2 Real-time vs standard profile data graph

| Aspect | Real-time profile data graph | Standard profile data graph |
|---|---|---|
| Profile at request time | SP calls the Data 360 profile API for the real-time profile | Lookup omitted; SP evaluates the profile JSON sent with the request |
| Freshness | "most up-to-date understanding of individuals, including any in-session behavior" | Whatever the caller sends; the graph refreshes on a schedule (default `Daily`) |
| Profile missing | `512 QUERY_SERVICE_MISSING_PROFILE` → processed as anonymous. `511 QUERY_SERVICE_ERROR` is a failed Query Service call, not a missing profile; that path may proceed as anonymous or return HTTP `503` | "blank, anonymous profile": profile-based targeting rules and profile-based recommender filters evaluate to false |
| Web Personalization Manager (WPM) | Points selectable | Points not listed |
| Documented use | Latency-sensitive web and mobile; "work across all personalization scenarios" | Outbound messaging, batch personalization |

Sources: [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_real_time_profile_data_graphs.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_standard_profile_data_graphs.htm&release=264.0.0&type=5) [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-pipeline-diagnostics.html) [src](https://help.salesforce.com/s/articleView?id=data.c360_a_create_a_data_graph.htm&release=264.0.0&type=5)

- Real-time pipeline: request (point IDs + individual ID) → profile API → decision/experiment eligibility from targeting rules → execute (Dynamic Content returns the configured attribute text; Recommendations call the recommendation service with the profile data graph and recommender ID) → return → log in Data 360. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_real_time_profile_data_graphs.htm&release=264.0.0&type=5)
- Standard pipeline: same minus the profile API call, keeping decisioning "in milliseconds, as standard data graphs are not optimized for real-time retrieval". [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_standard_profile_data_graphs.htm&release=264.0.0&type=5)
- Batch personalization and Marketing Cloud Growth/Advanced messages include the profile data graph automatically; any other caller of a standard-graph point must send it. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_standard_profile_data_graphs.htm&release=264.0.0&type=5)
- Where the JSON goes: Help says "in the context object of the request" [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_standard_profile_data_graphs.htm&release=264.0.0&type=5); the API defines a top-level `profile` ("If a profile is provided, the API always uses this profile and skips retrieving the profile from Data 360"), and `context` wins on duplicate keys across `context`, `events`, `profile`. [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-request-personalization.html)
- Contradiction: "Using Data Graphs With Personalization" still says the profile data graph "must be a real-time data graph" [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_data_graphs_using.htm&release=264.0.0&type=5), while the point-level articles support standard graphs [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_profile_data_graphs.htm&release=264.0.0&type=5). Treat the former as outdated.
- The Data 360 builder labels the standard type "near real-time data graph". [src](https://help.salesforce.com/s/articleView?id=data.c360_a_create_a_data_graph.htm&release=264.0.0&type=5)

### 1.3 Roots, identity resolution, accounts
- A recommender's profile data graph must contain a Profile-category DMO and have primary DMO `Unified Individual`, `Individual`, or `Account`. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_considerations.htm&release=264.0.0&type=5)
- Recommended root: the unified profile ("Unified Profile object") to use real-time identity resolution. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_data_graphs_using.htm&release=264.0.0&type=5) Data 360 allows any primary DMO category except Engagement. [src](https://help.salesforce.com/s/articleView?id=data.c360_a_data_graph_data_structures.htm&release=264.0.0&type=5)
- SP real-time match rule: Object `Party Identification`, Field `Identification Number`, Match Method `Exact`, `Match on Blank` unchecked, name ≤ 80 characters; reconciliation rules are identical in scheduled and real-time modes. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_real_time_identity_resolution_for_einstein_personalization.htm&release=264.0.0&type=5) Field lessons on reconciliation (keep web sources from blanking CRM values), draft-only graph field removal, session-extension lag and cross-object "Match to" pitfalls: [field-guide-data.md](field-guide-data.md) §1, §3.
- When an existing customer is identified, real-time insights and real-time segments are computed and saved to the real-time data graph record, which becomes available to SP. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_real_time_identity_resolution_for_einstein_personalization.htm&release=264.0.0&type=5)
- Web SDK events are ingested into the real-time layer and the standard layer simultaneously; unknown users get a new profile. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_data_cloud_and_einstein_personalization_learn_about.htm&release=264.0.0&type=5)
- `context.unifiedIndividualId` "isn't used for profile lookup"; it only partitions experiments when no lookup happens. [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-request-personalization.html)
- Accounts: send `profileId` instead of `individualId` ("You can also pass `individualId` as part of the `profileId` attribute"). [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-request-personalization.html) Account profiles are documented for rule-based recommenders (262). [src](https://help.salesforce.com/s/articleView?id=release-notes.rn_persnl_tailor_recommendations_for_accounts.htm&release=262.0.0&type=5)
- Real-time segmentation "doesn't run if an Account object and an Individual object are included in the same source data graph". [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_segments_using.htm&release=264.0.0&type=5)
- Account / B2B design options (documented constraints; the options are inference): new real-time graphs allow only 1:1 and 1:N, and "Standard data graphs continue to support N:1" [src](https://help.salesforce.com/s/articleView?id=data.c360_a_dg_n1_restriction.htm&release=264.0.0&type=5), so an Individual-rooted real-time graph can't pull its Account through a many-to-one hop; web `fetch` takes only point names (§5.3) and WPM lists only real-time points.
  - Identified web contacts: denormalize firmographics onto an Individual-level 1:N child or a CI keyed by the root, then use `Related Attributes` / `Calculated Insights` (WPM-compatible).
  - Portals or server-rendered pages: a standard graph with `<ACCOUNT_DMO>` via N:1, called server-side with the `profile` JSON, or `profileId` = `<ACCOUNT_ID>` on an Account-rooted graph (rule-based recommenders only, 262).
  - Anonymous visitors: firmographics from a third-party tool passed as dynamic context variables for recommender filters (not documented as targeting-rule inputs).
- Batch on a Unified Individual–rooted point: every linked individual would get the same output, so batch evaluates one individual ID per unified profile (and also writes the unified individual ID). [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_batch_create_batch_persnl.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_batch_persnl_faqs.htm&release=264.0.0&type=5)

### 1.4 What decisions can reference
- Targeting rules see everything accessible from the graph; segments, calculated insights and Einstein Studio models must first be created and applied or mapped to that graph. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_targeting_rules_create.htm&release=264.0.0&type=5)
- A calculated insight joins a data graph only if it's "based on a data model object (DMO) that's also included in the data graph", with that DMO's primary key as a CI dimension, and only at the graph root. [src](https://help.salesforce.com/s/articleView?id=data.c360_a_add_calculated_insights_to_a_data_graph.htm&release=264.0.0&type=5) Freshness in a decision is bounded by the CI schedule and the graph refresh (§1.6).
- Merge fields: direct attributes, related attributes, calculated insights, segment memberships of the profile data graph (§6.4). [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_point_decision_add_merge_fields.htm&release=264.0.0&type=5)
- `Profile Data Graph` recommendation filters require a calculated insight associated with the selected profile data graph. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_filters_configure.htm&release=264.0.0&type=5)

### 1.5 Default profile data graph per data space
- Setup → `Personalization Setup` → `Data Graph Defaults` tab → `Data Space` + `Default Profile Data Graph`; permission `Personalization Admin`. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_default_dg_to_ds.htm&release=264.0.0&type=5)
- Assignments are on by default; the toggle disables all of them for all data spaces (no per-space switch); editing a default doesn't change existing SP configurations. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_default_dg_to_ds.htm&release=264.0.0&type=5)
- The default pre-fills whenever that data space is chosen and can be overridden (262). The 262 preconfigured recommender use case deploys all assets, including a profile data graph, and requires that no profile data graph exists yet in the target data space. [src](https://help.salesforce.com/s/articleView?id=release-notes.rn_personalization.htm&release=262.0.0&type=5)

### 1.6 Data 360 data graph constraints that bound SP (264)

| Limit | Standard | Real-time |
|---|---|---|
| Data graphs per org | 25 | 25 (both raised from 10 on 2026-04-14) |
| Draft data graphs per org | 5 | 5 |
| Scheduled refreshes per day | 1 by default (changeable) | 24; active sessions refresh instantly; lakehouse copy hourly |
| JSON records per graph | 200 million | 100 million |
| Graph size | — | 200 KB (performance degrades above) |
| Objects per graph (primary + related + CIs) | 25 | 25 |
| Fields per DMO / total fields + measures | 50 / 200 | 50 / 200 |
| Measures per calculated insight included in a data graph | 5 | 5 |
| Engagement events | 100 | not stated |
| Max age of engagement data | 30 days (720 h) | 30 days (720 h) |
| Nesting below the primary DMO | 5 levels | 5 levels |
| Records per DMO | 1,000 (sort-and-limit default 100) | 1,000 |

Sources: [src](https://help.salesforce.com/s/articleView?id=data.c360_a_limits_and_guidelines.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=data.c360_a_changelog_usage_and_access.htm&release=264.0.0&type=5)

- The 5-measure cap is per calculated insight **included in a data graph**. A calculated insight itself may have up to 50 measures [src](https://help.salesforce.com/s/articleView?id=data.c360_a_limits_and_guidelines.htm&release=264.0.0&type=5).

- Real-time graphs support only 1:1 and 1:N; joins must use the parent DMO's primary key; N:1 is blocked for new graphs; existing N:1 graphs keep running but parent changes aren't immediately reflected. [src](https://help.salesforce.com/s/articleView?id=data.c360_a_create_a_data_graph.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=data.c360_a_data_graph_data_structures.htm&release=264.0.0&type=5)
- Real-time consumption settings: record caching keeps recently active known visitors in the real-time layer so the first page personalizes; disabling it can delay first-page personalization but stops consuming sub-second real-time entitlements. Session length: 30 min is the industry standard, 48 h the maximum; traffic spikes can end sessions early. [src](https://help.salesforce.com/s/articleView?id=data.c360_a_record_caching_in_rt_data_graphs.htm&release=264.0.0&type=5)
- Standard refresh options `Every 30 Minutes`, `Every 1 Hour`, `Every 4 Hours`, `Daily`, `Weekly`, `Monthly`, `Streaming` (default `Daily`); streaming rejects N:1 and ad hoc filters; builds take 15 minutes to several hours; creating a graph needs `Data Cloud Architect`. [src](https://help.salesforce.com/s/articleView?id=data.c360_a_create_a_data_graph.htm&release=264.0.0&type=5)
- Calculated-insight nodes get no default record limit; their sort-and-limit is opt-in, Connect API only, and can be updated but not removed. [src](https://help.salesforce.com/s/articleView?id=data.c360_a_limit_child_records_data_graph.htm&release=264.0.0&type=5)

[src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_data_graphs_using.htm&release=264.0.0&type=5) The quick start prescribes a real-time profile graph plus a standard item graph and says "Select a 30 minute refresh interval". - Catalog metadata (titles, descriptions, categories, attributes) powers cold start; items with good metadata are recommendable immediately. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_dlpr_cold_start.htm&release=264.0.0&type=5)
- Offer data graph recommenders include default filters on `Status`, `Start Date Time`, `End Date Time` (Real-Time Offer Management doc, adjacent product). [src](https://help.salesforce.com/s/articleView?id=mktg.offers_personalize.htm&release=264.0.0&type=5)

## 3. Personalization types: Recommendations vs Dynamic Content

| | Recommendations | Dynamic Content (formerly Manual Content) |
|---|---|---|
| Content source | Recommender built against a profile and an item data graph | Values typed into schema attributes, "stored on the personalization decision itself rather than in Data 360" |
| Typical use | 1:1 product, content or offer lists | Banners, infobars, pop-ups |
| Runtime | Personalizer calls the recommendation service | Returns the configured attribute text |
| Point-only setting | `Maximum Number of Recommendations to Return` | — |
| API value (`PersonalizationSchema.PersonalizationType`) | `Recommendations` (default) | `ManualContent` |
| Flow output collection | `persnlRecommendations` | `contentAttributes` (`attributeName`, `attributeValue`) |
| Personalization Campaigns (web only) | Not supported | Only supported type |

Sources: [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_content_schema_using.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_real_time_profile_data_graphs.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.mc_persnl_personalization_point_configure.htm&release=264.0.0&type=5) [src](https://developer.salesforce.com/docs/atlas.en-us.object_reference.meta/object_reference/sforce_api_objects_PersonalizationSchema.htm) [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/show-personalized-recommendations-in-flows.html) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_campaign_create.htm&release=264.0.0&type=5)

## 4. Content schemas (formerly response templates)
- Required for personalization points, Personalization Campaigns and decisions; defines the decision configuration form and a uniform, channel-independent response shape. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_content_schema_using.htm&release=264.0.0&type=5)
- Create: App Launcher → `Personalization Content Schema` → `New` → `Manual Setup` or `Use a Data Kit` (unmanaged kits only) → data space → type `Recommendations` or `Dynamic Content` → name (API name auto-generated) → `Next`. [src](https://help.salesforce.com/s/articleView?id=mktg.mc_persnl_personalization_schema_configure.htm&release=264.0.0&type=5)
- Personalization attributes: "Each personalization attribute specifies a text entry field" shown when configuring decisions (header text, CTA text, URL). No other data types, required flags or validation are documented. [src](https://help.salesforce.com/s/articleView?id=mktg.mc_persnl_personalization_schema_configure.htm&release=264.0.0&type=5)
- Dynamic Content schemas are saved after the attributes. Recommendations schemas continue to a response definition: [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_content_schema_configure.htm&release=264.0.0&type=5)
  - DMO: only item-graph roots are offered; its primary key is preselected (PK-only output lets a third-party system render the items).
  - Fields: move from `Available DMO Fields` to `Selected DMO Fields`; the arrows set the order in the response.
  - `Add Related Object Attributes`: up to 5 related objects for item variants (per-channel offer content, image variants).
- Related DMOs in content schemas arrived with indirect-signal offer objectives (262). [src](https://help.salesforce.com/s/articleView?id=release-notes.rn_personalization.htm&release=262.0.0&type=5)
- Two 264 articles share the title "Configure a Personalization Content Schema": `persnl_content_schema_configure` documents related objects but not data kits; `mc_persnl_personalization_schema_configure` the reverse. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_content_schema_configure.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.mc_persnl_personalization_schema_configure.htm&release=264.0.0&type=5)
- Web experience templates map content schema fields to the site's front-end output; a personalization experience connects a point, a template and a content zone. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_web.htm&release=264.0.0&type=5)
- Platform object `PersonalizationSchema` (API 62.0+) supports only read and describe calls (`query()`, `retrieve()`, `getUpdated()`, `getDeleted()`, describe). [src](https://developer.salesforce.com/docs/atlas.en-us.object_reference.meta/object_reference/sforce_api_objects_PersonalizationSchema.htm) DMO `std__PersonalizationSchemaDmo__dlm` holds `DataModelObjectId`, `IsActive`, `PersonalizationType`. [src](https://developer.salesforce.com/docs/data/data-cloud-dmo-mapping/guide/c360dm-si-personalizationschemadmo-dmo.html)
- Response `attributes` are keyed by attribute developer name [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-request-personalization.html), so renaming an attribute breaks renderers (inference). Edit or delete rules for a schema already in use are undocumented.

### 7.3 Rule-based
- Data graph resource: item graph (direct attributes, calculated insights) or profile graph (calculated insights and engagement attributes related to items, such as products or brands). [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_configure_rule_based.htm&release=264.0.0&type=5)

  1. Prereqs: view events land in an engagement DMO related 1:N to the profile root (for example Product Browse Engagement); the real-time profile graph holds its item ID and engagement date time; the item graph holds display and filter fields. Use the point's own profile graph (§1.1).
  2. Resource: the profile graph engagement attribute (engagement date). Required: a `Profile Data Graph` filter "to connect the item data graph product attribute with the related profile data graph's engagement attribute" [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_configure_rule_based.htm&release=264.0.0&type=5), e.g. `Include` → item ID → `Match Any` → engagement item ID (1:N right-hand side; no date operators in dynamic filters, so the graph's engagement lookback bounds recency, §7.6). Sort by engagement date and time descending [src](https://help.salesforce.com/s/articleView?id=release-notes.rn_persnl_sort_recommendations_for_recently_viewed.htm&release=260&type=5); sort field labels (UNVERIFIED).
  3. Optional: `Exclude` → item ID → `Decision Context` → current item (anchor required); `Static` availability flags. If the engagement attribute isn't offered in the filter, build a CI of viewed item IDs per individual (§1.4 filter prerequisite).
  4. Freshness: training refreshes every 24 h (§7.5); whether in-session views appear before the next run is undocumented, so `Simulate` right after a fresh view.
- Settings: `Calculated Insight`, `Sort Measure`, `Sort Order` (e.g., `Descending`). [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_exp_example_rule_based_recommender_configure.htm&release=264.0.0&type=5) Sorting by item-graph direct attributes or profile-graph CIs arrived in 260. [src](https://help.salesforce.com/s/articleView?id=release-notes.rn_personalization.htm&release=260&type=5)
- Co-bought: CI with two product dimensions + a count, count as `Sort Measure`, `Decision Context` filter on the viewed product. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_filters_configure_multiple_dimension_example.htm&release=264.0.0&type=5)

### 7.4 Objective-based
- Choose `Existing Objective` (predefined or saved custom) or `New Objective`; predefined objectives need their profile and item data graph configurations first. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_configure_objective_based.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_obj_based_recommender_data_graphs.htm&release=264.0.0&type=5)
- Custom-objective prerequisites: the profile graph includes the engagement signals' DMOs and fields (user ID, timestamp, unique ID) and every filter field; the item graph includes the item identifier. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_configure_objective_based.htm&release=264.0.0&type=5)
- Custom objective: name → purpose → count-based engagement signal metric → extra training signals (only those compatible with both graphs). [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_create_custom_objective.htm&release=264.0.0&type=5)
- Offers with indirect signals: the metric's item identifier is the offer; the profile graph holds both the indirect item (offer) and the direct item (product or form); the conversion event records the applied offer, or the promotion if offers are N:1 to promotions; extra signals use the direct conversion item. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_create_custom_obj_for_offers.htm&release=264.0.0&type=5)
- Minimum training: at least 3 engagement activities across the engagement objects the recommender references. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_considerations.htm&release=264.0.0&type=5)

### 7.5 DLPR, training, cold start
- DLPR learns full engagement sequences across all users (next-item prediction, "similar to how large language models … predict the next word"), weights by business reward, generates recommendations in real time, and trains only on your data. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_dlpr.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_machine_learning_for_objective_based_recommenders.htm&release=264.0.0&type=5)
- DLPR "doesn't use demographic data, personally identifiable information beyond engagement interactions, or data purchased from third parties". [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_machine_learning_for_objective_based_recommenders.htm&release=264.0.0&type=5)
- Cold start is "the only automatic switch": new site → semantic embeddings of catalog content; new item → catalog content stands in; promotions without history → semantically similar promotions. Nothing to configure. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_dlpr_cold_start.htm&release=264.0.0&type=5)
- Training: the recommender must be `Active`; refresh every 24 h for all rule-based and active objective-based recommenders (Limits page: full recommender data refresh `Daily`); `Latest Refresh Status` = `Processing`, `Complete`, `Failure` (retried within 24 h; contact Support after more than two failed cycles; the last successful refresh keeps serving); usable in points after one successful refresh (`Last Successful Refresh`). [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_recommender_training_track_status.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_basics_limits.htm&release=264.0.0&type=5)
- Conflict: DLPR "retrains on a scheduled cadence" whose frequency "varies based on data volume and business unit configuration". [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_dlpr.htm&release=264.0.0&type=5)

### 7.6 Recommendation filters
- Recommender → `Edit` → Filters page → `Include` or `Exclude` tab → `All conditions are met` / `Any condition is met` → `Add Condition` → item data graph resource (direct attribute, related attribute, calculated insight) → filter type → operator → value or anchor. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_filters_configure.htm&release=264.0.0&type=5)
- Limits: 10 conditions per include or exclude filter; top 100 item-graph CI values (dimensions + measures) considered; 100 profile-graph values per condition; 100 DMO values per comparison. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_basics_limits.htm&release=264.0.0&type=5)

| Filter type | Compares the catalog field with | Prerequisite |
|---|---|---|
| `Decision Context` | The item the visitor is viewing | Anchor item in the request (`anchorId`) (inference) |
| `Static` | A fixed value or a dynamic context variable | — |
| `Profile Data Graph` | Visitor behavior and history | CI on the selected profile data graph |

Source: [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_filters_configure.htm&release=264.0.0&type=5)

| Operator | `Static` data types | `Decision Context` / `Profile Data Graph` |
|---|---|---|
| `Has Value`, `Has No Value` | Text, Number, Date | — |
| `Is Equal To`, `Is Not Equal To` | Text, Number | Text, Number (`Is Equal To` requires a value, doesn't evaluate nulls) |
| `Is Less Than`, `Is Less Than Or Equal To`, `Is Greater Than`, `Is Greater Than Or Equal To` | Number | Number |
| `Is Between` | Number, Date, DateTime (inclusive) | — |
| `Is Today`, `Last Number of Days`, `Next Number of Days` | Date, DateTime | — |
| `Is Before Current DateTime`, `Is After Current DateTime` | Date, DateTime | — |
| `Is Subset` | — | Text; 1:N on both sides |
| `Match Any`, `Does Not Match` | — | Text; right-hand resource 1:N |

Source: [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_filters_operators.htm&release=264.0.0&type=5)

- Static filters evaluate in the org time zone; date operators don't exist for dynamic comparisons. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_filters_operators.htm&release=264.0.0&type=5)
- `Is Before Current DateTime`: include on StartDate (active) or exclude on EndDate (expired). `Is After Current DateTime`: include on EndDate (not expired) or exclude on StartDate (future launches). Leave the value blank for system time; both added in 260. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_filters_operators.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=release-notes.rn_personalization.htm&release=260&type=5)
- `Is Subset`: `Profile Data Graph` or `Decision Context` only; 1:N attributes only (not direct attributes); ≤ 100 attributes per dataset; an empty catalog field matches everyone. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_filters_is_subset.htm&release=264.0.0&type=5)
- Recipes: in stock (`Include` + `Static` + `Is Equal To`); hide expired (`Exclude` + `Is Before Current DateTime`, blank value); same color (`Decision Context` + `Match Any`); unexplored categories (`Profile Data Graph` + `Does Not Match`); exclude purchased (`Exclude` + `Profile Data Graph` + `Is Equal To` against a CI of past product IDs). [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_filters_operators.htm&release=264.0.0&type=5)
- Promotion eligibility (all or any segments, loyalty tier, current product or category, not yet purchased, partner products); SP "does not enforce end-stage validation criteria, such as meeting a minimum spend at checkout". [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_example_filters_for_promotion_eligibility_criteria.htm&release=264.0.0&type=5)
- Label drift: `Matches` (dynamic-variable and co-bought articles), `isSubset` / `match any` (promotion examples), `Less Than` / `Greater Than` / `Between` and `Last/Next Number of Minutes` (dynamic-variable article and dev guide only). [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_filter_using_dynamic_variable.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_filters_configure_multiple_dimension_example.htm&release=264.0.0&type=5) [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/set-up-dynamic-context-variables.html)

### 7.7 Dynamic context variables
- A `Static` filter value in Salesforce Merge Language, e.g. `{!category}`, resolved from the request; if the request lacks it, the filter is discarded. ≤ 64 alphanumeric/underscore characters, no prefix or suffix, one variable per static filter; dates `yyyy-MM-dd` or `yyyy-MM-ddTHH:mm:ss.SSSZ`. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_filter_using_dynamic_variable.htm&release=264.0.0&type=5) Number and date placeholders arrived in 262. [src](https://help.salesforce.com/s/articleView?id=release-notes.rn_personalization.htm&release=262.0.0&type=5)
- Web: `contextualAttributes` in the sitemap `global` config or per `pageTypes` entry; value = string, function or promise. [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/set-up-dynamic-context-variables.html) Mobile: `contextualAttribute(name:value:)`. [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-android.html) REST: custom context variable in `context`, which "isn't recorded in Data 360". [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-request-personalization.html)
- Reserved attributes: `anchorId`, `anchorType`, `locale`, `pageType`, `interaction` can be overridden; `dataspace`, `individualId`, `channel`, `channelContext`, `requestUrl`, `p13n_sys_requestTimeZone` and UTM fields can't; a valid SDK value overwrites a custom one. `anchorType` is "The Data Model Object name associated with the anchor item"; set it with `anchorId` in a page type's `contextualAttributes`. Context variables work with string, number and date filter fields, single-value operators, **Between** and **Last/Next Number of Days/Minutes**. [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/set-up-dynamic-context-variables.html) Mobile `anchorDmoName` (e.g. `ssot__GoodsProduct__dlm`): "If omitted, the system infers the anchor type from `anchorId` automatically." [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-android.html)

[src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-pipeline-diagnostics.html)

[src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_set_up_fallback_Recmdr.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=release-notes.rn_personalization.htm&release=262.0.0&type=5)

Locale order: decision request → profile locale → default language and currency. Field level: an attribute absent from the localization schema falls back to the root DMO default; a defined-but-blank attribute stays blank. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_localization_configure.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_localization_using.htm&release=264.0.0&type=5)

## 8. Real-time layer as used by SP
- Flow: Web SDK → real-time + standard layers → real-time identity resolution (profile created if unknown) → real-time graph updated → real-time insights and segments recomputed → SP fetches the profile through the profile API. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_data_cloud_and_einstein_personalization_learn_about.htm&release=264.0.0&type=5)
- Real-time segments: add Segment ID and Timestamp from the segment membership DMO to the real-time profile graph; max 35; one engagement DMO; one streaming event; one nesting level; no exclusions, segment counts or manual publish; creating one needs `Data Cloud Architect`. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_segments_using.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=data.c360_a_create_a_realtime_segment.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=data.c360_a_limits_and_guidelines.htm&release=264.0.0&type=5)
- Calculated insights are "near real time and best used when creating metrics associated with items or products, not for real-time Personalization applications" (SQL or Visual Builder). [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_insights_using.htm&release=264.0.0&type=5)
- Real-time insights: built only on real-time data graphs, Visual Builder only (no SQL); add every dimension and measure to the graph first; max 20 insights, 15 fields, 10 related DMOs. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_insights_using.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=data.c360_a_limits_and_guidelines.htm&release=264.0.0&type=5)
- Real-time calculated affinity: App Launcher → `Calculated Affinity` → `New` → data space, lookback window, optional decay → real-time profile graph (Individual or Unified Individual root) → object related to ≥ 1 engagement object → mapped text fields → 1–10 engagement signals with strength `high`/`medium`/`low` (5/3/1 points) and positive or negative impact. Permissions `Calculated Affinities`, `Data Graph Definitions`, `Engagement Signals`. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_calculated_affinities_rt_configure.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_calculated_affinities_how_calculated.htm&release=264.0.0&type=5)
- Affinity output: one CI per selected field, auto-added to the real-time profile graph, named from the affinity and field (e.g., "Product Affinity Brand"; CI names ≤ 40 characters, truncation risk); base score 0–100 plus unbounded raw score; decay recomputed in batch on the CI schedule (hourly for real-time CIs) down to 1% over the lookback. Usable in targeting, recommendation filters, segmentation and agent grounding. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_calculated_affinities_using.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_calculated_affinities_how_calculated.htm&release=264.0.0&type=5)
- Einstein Studio (now AI Models) predictions: models built from scratch with Model Builder (connected models unsupported), activated, and mapped on the model's `Integrations` tab (personalization map: data space + real-time profile data graph + fields); inputs are direct attributes and number-type CIs without dimensions; then usable as `Predictive Models` in targeting rules. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_esi_realtime_prediction_for_persnl.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=data.c360_a_ai_ec_personalized_recommendations.htm&release=264.0.0&type=5)

| Needs a real-time profile data graph | Works with a standard profile data graph |
|---|---|
| Points selectable in WPM | Outbound messaging and batch personalization |
| In-session behavior in eligibility and decisions | Decisions on profile JSON supplied by the caller |
| Real-time segments, real-time insights, real-time calculated affinities | Standard segments and calculated insights on the graph (inference) |
| Einstein Studio predictions in targeting rules | — |

### 8.1 Frequency capping (no native feature; pattern built from documented parts)
- SP has no frequency cap; frequency limits exist only for **MCP** triggered campaigns [src](https://help.salesforce.com/s/articleView?id=mktg.mc_pers_triggered_campaign_trigger_frequency.htm&release=264.0.0&type=5) (MCP). WPM overlays offer only `Immediately`, `Exit Intent`, `Element Click`, `Scroll Percentage` (wpm-experiences-campaigns.md §3).
- Pattern (each step documented; the combination isn't a doc example, so validate in a sandbox):
  1. Separate the capped experience's events with a custom engagement destination (doc example key `popupEngagement`): `'event-type': 'userEngagement'`, `'interaction-name': (context) => context.name === 'view' ? '<CAPPED_VIEW_NAME>' : '<CAPPED_CLICK_NAME>'`, `disableSendingNonItemEngagementEvents: false` for Dynamic Content (omit `type`, valid only for product recommendations); pass it as `customEngagementConfig` and select it in WPM `Engagement Destination` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/track-personalization-engagement.html).
  2. Add Website Engagement (channel action, date time) to the real-time profile data graph.
  3. Real-time insight (Visual Builder): filter the channel action = `<CAPPED_VIEW_NAME>`; relative time filter `DateTime` → `Relative DateTime` → `Interval` = `<WINDOW>`; measure `Count` (only Sum and Count) [src](https://help.salesforce.com/s/articleView?id=data.c360_a_create_real_time_insight.htm&release=264.0.0&type=5). No events → 0; windows are rolling and bucketed ("approximate metric") [src](https://help.salesforce.com/s/articleView?id=data.c360_a_insight_relative_time_metrics.htm&release=264.0.0&type=5).
  4. Decision on the capped point: `All Conditions Are Met` + `Calculated Insights` → insight below `<N>` (operator labels unpublished, §6.3), and no `Always (No Rules)` catch-all, so a capped visitor gets `NO_DECISION_QUALIFIED` and nothing renders.
- Limits: rolling window only (no calendar-day function documented); "per visitor" = per real-time profile (device-level while anonymous); the doc says graph clients "must process the real-time insight data from the client side", so whether SP applies the window exactly is undocumented; test with a live profile. Real-time segments allow no exclusions (§8), so prefer the insight route.
- Fallback: a client-side "last shown" flag checked in a Content Zone Handler `onReady`; per browser only, the decision is still requested and billed, and it needs the site owner's consent sign-off (inference).

## Design guidance
- Real-time vs standard: real-time for web, mobile, WPM, in-session rules, real-time segments/insights/affinities and model predictions; standard for outbound and batch, where the profile is supplied (automatic for batch and Marketing Cloud Growth/Advanced). A caller that hits a standard-graph point without profile JSON gets every profile-based rule evaluated false. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_real_time_profile_data_graphs.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_standard_profile_data_graphs.htm&release=264.0.0&type=5)
- Dynamic Content when content is authored per decision (banners, infobars, CTA text) or built through Personalization Campaigns; Recommendations when items come from an item data graph, with schema attributes for surrounding text. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_content_schema_using.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.mc_persnl_personalization_schema_configure.htm&release=264.0.0&type=5)
- Order decisions most specific first; end with an `Always (No Rules)` catch-all, since no default decision exists (inference); keep work in progress in `Draft`; budget for the 25-decision cap per point. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_decision_add.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_basics_limits.htm&release=264.0.0&type=5)
- Test through the authenticated endpoint: `decisionId` (bypasses rules), `EnableDiagnostics`, `TestMode` (no data-lake outputs). [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-request-personalization.html)
- Group requests by profile data graph; one request can't mix graphs. [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-request-personalization.html)
- Keep real-time graphs under 200 KB, free of N:1, and limited to fields that rules, merge fields and filters use; add CIs, segment ID + timestamp, and model maps before writing rules. [src](https://help.salesforce.com/s/articleView?id=data.c360_a_limits_and_guidelines.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=data.c360_a_create_a_data_graph.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_targeting_rules_create.htm&release=264.0.0&type=5)
- Recommenders are scarce (10 per org): prefer dynamic context variables over cloning recommenders per category. Budget lead time (3 engagement activities, then one successful 24 h refresh), attach a fallback on the same data space and graphs, and simulate with anchor items before go-live. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_basics_limits.htm&release=264.0.0&type=5) [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/set-up-dynamic-context-variables.html) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_recommender_training_track_status.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_set_up_fallback_Recmdr.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_simulate_recommender.htm&release=264.0.0&type=5)
- Put every filter field in the item graph and gate validity with `Is Before/After Current DateTime` on start and end dates; enforce checkout rules (e.g., minimum spend) outside SP. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_item_dg_for_max_rev_with_prom.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_example_filters_for_promotion_eligibility_criteria.htm&release=264.0.0&type=5)
- Content schemas: PK-only for external rendering, selected fields for self-rendering, related objects for variants; treat attribute developer names as a stable contract with renderers (inference). [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_content_schema_configure.htm&release=264.0.0&type=5)
- Size affinity thresholds to realistic signal volume; a high minimum with few low-strength signals qualifies almost nobody. [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_calculated_affinities_how_calculated.htm&release=264.0.0&type=5)

## Gaps and uncertainties
- No SP article lists targeting-rule operators or value types, or states the time zone `Scheduling` uses (`p13n_sys_requestTimeZone` exists; its role is (UNVERIFIED)).
- Content schema attribute data types, required flags, and edit/delete behavior after a schema is in use are undocumented; the UI calls each attribute a "text entry field".
- Org counts of points and content schemas, and the maximum points per decisioning request, are undocumented. Whether the UI blocks a 26th decision or a `Maximum Number of Recommendations to Return` above 24 is (UNVERIFIED); the Limits page is the only source for both.
- Decision priority numbers conflict across the platform object, the DMO and the campaign wizard (§6.2); UI order is the only unambiguous signal.
- Training cadence: 24 h / `Daily` (training and Limits pages) vs "varies" (DLPR article) (§7.5).
- The rule-based article's item-graph root restriction is probably a doc error (§7.2).
- "Using Data Graphs With Personalization" requires a real-time profile graph, contradicting standard-graph support (§1.2).
- Profile JSON location: Help says `context`, the API has top-level `profile` (§1.2).
- Filter operator labels differ between articles (§7.6); `Batch Status` meaning conflicts (§9).
- Permission names drift: `Change and Edit Personalization Points`, `Create and Edit Personalization Points`, `Create and Edit Personalization Points or Campaigns`; the localization article's permission reads only "Change and Edit".
- Merge field token syntax is known from one example (`{first_name}`); escaping and formatting are undocumented.
- Account-rooted graphs are documented for rule-based recommenders only. Undocumented: Account-rooted points in WPM; targeting rules, merge fields or objective-based recommenders on Account graphs; how the Web SDK keys a decision to an account (§1.3).
- Einstein Studio predictions on standard-graph points: models map to real-time profile graphs; other behavior (UNVERIFIED).
- The `9pb` decision prefix, the `0Wl` setup-URL ID, and the empty `data` array for Dynamic Content are field observations only; DMO IDs (max 15 characters) vs 18-character API IDs need normalization (inference).
- The authenticated endpoint doc omits `EnableDiagnostics` from `executionFlags` (diagnostics are always returned there).
- Older admin releases aren't indexed; pre-264 differences come from release notes only. The DLPR retraining schedule must be requested from Salesforce.

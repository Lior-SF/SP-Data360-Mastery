# Mobile, Server-Side, Batch and AI Channels

## Scope

- Salesforce Personalization (SP) delivery outside the Web SDK: the Personalization module of the Engagement Mobile SDK (pro-code and low-code), the Decisioning API and other server-side entry points, batch decisions for Data 360 segments, Agentforce, Marketing Cloud Next (MC Next) email/landing pages, and AI Models (formerly Einstein Studio) predictions.
- Authoritative: SP developer guide (`developer/einstein-personalization`), Data 360 Engagement Mobile SDK docs (`developer/data-cloud`), SP Help (`persnl_*`, breadcrumb `Salesforce Help|Docs|Salesforce Personalization`), Data 360 Help, release notes. Release 264.0.0 unless stated.
- Pages with other breadcrumbs are flagged inline (Agentforce, MC Next, Marketing Cloud Engagement (MCE), Real-Time Offer Management, **MCP** = Marketing Cloud Personalization). MCP facts appear only in "MCP confusion traps".
- Tags: (UNVERIFIED) = not confirmed in docs; "doc conflict" = two official pages disagree (see Gaps).

### 1.3 Prerequisites and connector setup
- Data 360 mobile app connector (`Websites and Mobile Apps`) supplies `appId` (same value as `appSourceId` in the network layer, a UUID) and the tenant-specific endpoint [src](https://developer.salesforce.com/docs/data/data-cloud-engagement-mobile-sdk/guide/c360a-api-engagement-mobile-sdk-initialization-v3.html).
- Pro-code needs **CDP_APP_ID**, **CDP_ENDPOINT**; low-code also **CDN_URL**, **DATASPACE** and a custom URL scheme for live preview [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-procode.html), [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode.html).
- Help setup phases [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_mobile_personalization_setup.htm&release=264.0.0&type=5): I app + connector (init SDK, send engagement/profile data, in-app URL, register components and content zones) → II engagement tracking (once per content schema) → III mobile experience templates (reference a component, not HTML) → IV experiences (create, QR preview, publish).
- Permissions: `Data Cloud Architect` to configure the mobile app connection; `Data Cloud admin` to register components, content zones and tracking; `Personalization user` to create experiences [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_mobile_app_configure.htm&release=264.0.0&type=5), [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_mobile_components_register.htm&release=264.0.0&type=5), [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_mobile_create.htm&release=264.0.0&type=5).
- UI path: `Data Cloud Setup` → `Websites and Mobile Apps` → mobile connector → `Personalization` tab:
  - `Mobile Preview Base URL` = the app's custom scheme, e.g. `myapp://personalization-preview` [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_mobile_app_configure.htm&release=264.0.0&type=5).
  - `Mobile Personalization Configuration` → `Components` → `Add Component` (`Component Name`, `Description`) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_mobile_components_register.htm&release=264.0.0&type=5).
  - `Content Zones` → `Add Content Zone` (`Content Zone Identifier`, `Label`, `Description`; move components from `Available Components` to `Connected Components`). A zone lists only its allowed components, and experience setup lists only zones that support the template's component [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_mobile_content_zones_register.htm&release=264.0.0&type=5).

### 1.5 Initialization
```swift
let cdp = CdpConfigBuilder(appId: "<connector appId>", endpoint: "<tenant endpoint>").build()
let p13n = PersonalizationConfigBuilder().dataspace("default") /* low-code: .cdnUrl("<CDN URL>") */ .build()
SFMCSdk.initializeSdk(ConfigBuilder().setCdp(config: cdp).setPersonalization(config: p13n).build()) { statuses in }
```
```kotlin
SFMCSdk.configure(this, SFMCSdkModuleConfig.build {
    cdpModuleConfig = cdpConfig
    personalizationModuleConfig = PersonalizationConfig.Builder(this).dataspace("default") /* low-code: .cdnUrl("<CDN URL>") */ .build()
}) { initStatus -> }
```
- Init once in `application(_:didFinishLaunchingWithOptions:)` (SwiftUI: the `App` type's `init()`) or `Application.onCreate()`, never in a view controller/Activity; same `Application` context for both builders; `default` data space if none set [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-ios.html), [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-android.html), [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-ios.html).
- Low-code (iOS and Android) queues content-zone requests made before init completes [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-android.html).
- Data 360 module options: `trackScreens` / `trackLifecycle` default `false`; `sessionTimeoutInSeconds` default `600`; `eventFlushRate` default 20 events, interval variant must not go below 30 s (iOS interval in seconds, Android in ms) [src](https://developer.salesforce.com/docs/data/data-cloud-engagement-mobile-sdk/guide/c360a-api-engagement-mobile-sdk-initialization-v3.html).
- Debug logging before init: `SFMCSdk.setLogger(logLevel: .debug)` / `SFMCSdk.setLogging(LogLevel.DEBUG, AndroidLogger())`; remove for production; read IDs from `Info.plist` / `<meta-data>` / build config rather than committing them [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-android.html).

### 1.6 Fetching decisions (pro-code)
| Step | Pro-code [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-procode.html) | Low-code [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode.html) |
|---|---|---|
| 1 | init Data 360 + Personalization modules | init the Personalization module |
| 2 | call `fetchDecisions()` with point API Name(s) | place a `ContentZone` with allowed components |
| 3 | SDK returns `DecisionsResponse` | SDK fetches a decision |
| 4 | app parses and renders its own UI | matching component renders, else optional fallback |
| 5 | app reports `View`/`Click` itself | OOTB components track automatically |

- iOS: `PersonalizationModule.fetchDecisions(personalizationPointNames:decisionsRequestContext:timeoutSeconds:) async throws -> DecisionsResponse` (default 10 s); Obj-C `[SFPersonalizationModule fetchDecisionsWithPersonalizationPointNames:context:timeoutSeconds:error:]` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-ios.html).
- Android: suspend `PersonalizationSdk.fetchDecisions(personalizationPointNames, decisionsRequestContext, timeoutMs)` → `Result.Success` (`output`) / `Result.Failure` (`throwable: PersonalizationException`); callback overload adds `scope`, `callbackDispatcher` (default `Dispatchers.Main`), `callback` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-android.html).
- Pass point **API Names**, not labels; several points per call; one context applies to all points; "Grouping personalization point names by datagraph is the responsibility of the caller" [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-android.html).
- Context builder `DecisionsRequestContextBuilder()` / `DecisionsRequestContext.Builder()`: `.anchorId(...)`, `.anchorDmoName("ssot__GoodsProduct__dlm")` (inferred from `anchorId` if omitted), `.contextualAttribute(name:value:)` once per pair [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-ios.html). Flutter uses `anchorType`; `anchorDmoName` is a deprecated alias there [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-flutter.html).
- `DecisionsResponse` {`requestId`, `personalizations`, `personalizationsByName` (preferred)}; each `DecisionsResponsePersonalization` {`personalizationPointName`, `personalizationId`, `attributes`, `data` (items with `personalizationContentId`), `decisionId`; Android also `personalizationPointId`} [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-ios.html), [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-android.html).
- iOS errors: `PersonalizationError` `.initialization`, `.consent`, `.timeout`, `.responseInvalid`, plus `.unknown`, `.requestInvalid`, `.network` (low-code table); `CancellationError` on cancel [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-ios.html).
- Android errors: `PersonalizationException.Type` `UNKNOWN`, `INITIALIZATION`, `CONSENT` (not opted in), `REQUEST_INVALID`, `NETWORK`, `RESPONSE_INVALID`, `TIMEOUT` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-android.html).

### 1.7 Rendering (low-code)
- `ContentZone` parameters (iOS/Android): `name` (required, case-sensitive match to the registered zone), `allowedComponents` (required), `decisionsRequestContext`, `timeoutSeconds` (iOS, default 10) / `timeoutMs` (Android, default 10,000), `controller` (`ContentZoneController`, `refresh()`), `loading`, `fallback`. Unlisted component → fallback; no fallback → error logged, nothing shown [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-ios.html), [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-android.html).
- Name matching differs by wrapper: React Native trims/lowercases names and the last duplicate wins; Flutter is case-insensitive and the first duplicate wins [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-reactnative.html), [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-flutter.html).
- OOTB `SalesforceBanner` / `SalesforceRecommendations`, backed by templates `Salesforce_Banner` / `Salesforce_Recommendations`; `onTap` overrides the default (open `ctaUrl`); styling via e.g. `BannerStyle(...)` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode.html). Help lists the banner API name as `Salesforce_Personalization_Banner` (doc conflict) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_mobile_components_register.htm&release=264.0.0&type=5).
- Custom components: iOS `Component` (`static var name`, `validateAndCreateComponentModel(unvalidatedJson:componentContext:)`, `compose(model:componentContext:)`); Android `Component<Model>` (`name`, `modelClass`, `validateAndCreateComponentModel(unvalidatedJson, componentContext)` → `Result`, `@Composable Compose(model, componentContext)`). Name must match the experience template's component name; model fields/types must match the template schema [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-ios.html), [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-android.html).
- Preview: a URL containing `sfp-preview` renders preview content in all active zones; route via `PersonalizationModule.handlePreviewURL(url)` (iOS) or `PersonalizationSdk.handlePreviewIntent(intent)` in `onCreate`/`onNewIntent` (Android); needs URL scheme/Universal Links/app links plus the connector base URL [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-android.html). RN/Flutter: `PersonalizationModule.handlePreviewUrl(...)`, preview refetches only the matching zone; custom schemes only on controlled devices, verified Universal/App Links for production; treat preview URLs/tokens as sensitive [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-reactnative.html), [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-flutter.html).
- Design-time mocks: `MockDataContentZone` (iOS, Android, Flutter), `MockContentZone` (React Native); no network, no engagement.
- Experience creation: point → experiences `New` → `Channel` mobile + `Connector` → `Experience Template` (filtered by the point's content schema) → `Display Method` = `Mobile Content Zone` → `Content Zone` → preview → publish [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_mobile_create.htm&release=264.0.0&type=5).

|---|---|---|
| Rendering | OOTB (Banner, Recommendations) or custom components | fully custom UI |
| Engagement tracking | automatic for OOTB; assisted (SDK APIs) for custom | manual |
| Runtime flexibility | change point/content without code, within the zone's allowed components | low |

### 1.8 Engagement tracking
- Connector config (web and mobile): `Personalization Engagement Tracking` → `Add Tracking Event` → `Content Schema`, `Event Type` (a Data 360 engagement event; profile/cart/order events unsupported), per-field `Mapping Type` = `Content Schema Attribute` | `Action` | `Static Value`; `Advanced Settings`: `View Action` = `personalization-view`, `Click Action` = `personalization-click`, optional `Dismiss Action`. One config per content schema applies to every point using it. Native components must call the tracking APIs for events to be sent [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_mobile_engagement_tracking.htm&release=264.0.0&type=5).
- Landing DMO = the Data 360 engagement event chosen as `Event Type`, mapped through the connector's stream. For attribution, pick an event whose stream maps `personalizationContentId` into a DMO with the Personalization Log foreign key (measurement-and-attribution.md §1.6); for media and content apps, Media Engagement carries that FK plus Digital Content / Electronic Media FKs [src](https://developer.salesforce.com/docs/data/data-cloud-dmo-mapping/guide/c360dm-si-mediaengagementdmo-dmo.html).
- OOTB components track `View` and `Click` — "the only two actions currently supported end-to-end" [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-android.html).
- Custom-component APIs:
  - iOS: `componentContext.trackEngagement(action:)`, `componentContext.trackEngagementPerItem(index:action:)`, modifiers `.sfpTrackEngagementViewOnce(componentContext)`, `.sfpTrackEngagementViewOncePerItem(componentContext, index:)` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-ios.html).
  - Android: `componentContext.trackEngagement(EngagementAction.CLICK)`, `componentContext.trackEngagementPerItem(index, action)`, composables `TrackEngagementViewOnce(componentContext)`, `TrackEngagementViewOncePerItem(componentContext, index)` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-android.html).
  - React Native: `useTrackEngagementViewOnce(context)`, `trackEngagement(context, action)`, `useTrackEngagementViewOncePerItem(context)` (attach the returned handler to `onViewableItemsChanged`), `trackEngagementPerItem(context, index, action)` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-reactnative.html).
- Pitfalls: built-in View fires on mount/render, not verified visibility; view-once dedupes by the exact `ComponentContext` object (never copy it); invalid recommendation items are skipped without remapping indices, so later events can be misattributed; preview usually carries no engagement payloads [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-flutter.html), [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-reactnative.html).
- Pro-code reports `View`/`Click` "manually using the SDK's tracking APIs"; method names are not on the pro-code pages (gap) [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-procode.html).

### 1.9 Consent and identity (Data 360 module)
- States: `Consent.optIn`/`OPT_IN` (send; flush queue), `Consent.optOut`/`OPT_OUT` (never queued; queue deleted), `Consent.pending`/`PENDING` (default for a new module, SDK-managed). Pending — iOS blocks engagement and profile events (lifecycle/screen allowed) and generates a new `deviceId` on opt-in; Android queues and flushes on opt-in. Assigning `PENDING` on Android throws `IllegalArgumentException` [src](https://developer.salesforce.com/docs/data/data-cloud-engagement-mobile-sdk/guide/c360a-api-engagement-mobile-sdk-consent-management-v3.html).
- Set/read: iOS `CdpModule.shared.consent = .optIn` or `CdpModule.shared.setConsent(consent: .optIn)`, `CdpModule.shared.getConsent()`; Android `CdpSdk.requestSdk { sdk -> sdk.consent = Consent.OPT_IN }` [src](https://developer.salesforce.com/docs/data/data-cloud-engagement-mobile-sdk/guide/c360a-api-engagement-mobile-sdk-consent-management-v3.html). RN/Flutter wrappers: `PersonalizationModule.setConsent(...)`, `isConsentOptIn()` (false for both unset and opt-out); mount live zones only after opt-in succeeds [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-reactnative.html).
- "In your production application, you must explicitly manage user consent" [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-ios.html); `SFMCSdk.track(event:)` is silently dropped under opt-out or when blocked in pending [src](https://developer.salesforce.com/docs/data/data-cloud-engagement-mobile-sdk/guide/c360a-api-engagement-mobile-sdk-capturing-engagement-data-v3.html).
- Profile: `SFMCSdk.identity.edit { identity in identity.addAttributes(attributes: [...]); return identity }` / `sdk.identity.edit { attributes.put(...) }`; contact point events emit only when required fields (`email`; `phoneNumber`; `addressLine1`+`city`+`stateProvince`+`country`) are present and changed; users are known by default — anonymous via `isAnonymous` = `"1"` or `CdpModule.shared.setProfileToAnonymous()` / `setProfileToKnown()`; when a `profileId` is set (e.g. by MobilePush for a resolved subscriber) the module sends `partyIdentification` (`userId`, `IDName`, `IDType`) [src](https://developer.salesforce.com/docs/data/data-cloud-engagement-mobile-sdk/guide/c360a-api-engagement-mobile-sdk-capturing-profile-data-v3.html).
- Shared identity across modules, e.g. `SFMCSdk.identity.setProfileId(email, [.cdp, .push])` [src](https://developer.salesforce.com/docs/marketing/engagement-mobile-sdk/guide/intro-engagement-mobile-sdk.html).

### 2.2 Request and response
- `context`: `individualId` or `profileId` (accounts; may carry the individual ID), `unifiedIndividualId` (experiment partitioning only, not lookup), `dataspace`, `anchorId`, `anchorType`, `correlationId` (multi-request attribution), `messageId`, `requestUrl` (UTM parsing), `customContextVariable` (recommender filters; not recorded). Context is recorded in the Personalization Record DLO; on duplicate keys `context` beats `events`/`profile` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-request-personalization.html). The authenticated page omits `profileId`, `customContextVariable` and `EnableDiagnostics` from its tables [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-authenticated-request.html).
- `personalizationPoints[]`: `id` | `name`, optional `decisionId` (return that decision without rule evaluation, for testing); all points must share the profile data graph [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-request-personalization.html). `decisionId` on an unauthenticated call → HTTP `400` (code 408) [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-pipeline-diagnostics.html).
- `profile`: a Data 360 hot-layer profile; when supplied, lookup is skipped [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-request-personalization.html). Points on a standard (non-real-time) profile data graph skip lookup — include the profile data graph JSON (Help says "in the context object") or rules evaluate a blank anonymous profile; batch and MC Growth/Advanced sends do this automatically; WPM lists only real-time-graph points [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_standard_profile_data_graphs.htm&release=264.0.0&type=5).
- `executionFlags`: `TestMode` (no outputs recorded to the data lake), `ContextOnly` (no profile lookup), `EnableDiagnostics` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-request-personalization.html).
- Response: `personalizations[]` {`personalizationId`, `personalizationPointId`, `personalizationPointName`, `data[]` (`personalizationContentId` + schema fields), `attributes`, `diagnostics`}, top-level `diagnostics`, `requestId`; diagnostics "Available only for authenticated requests" [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-authenticated-request.html).

```bash
curl "https://{tenantSpecificEndpoint}/personalization/authenticated/decisions" \
  -X POST -H "Authorization: Bearer $DATA_CLOUD_ACCESS_TOKEN" -H "content-type: application/json" \
  -d '{"context": {"individualId": "<id>", "dataspace": "default", "anchorId": "<sku>",
                   "anchorType": "ssot__GoodsProduct__dlm"},
       "personalizationPoints": [{"name": "<Point_API_Name>"}],
       "executionFlags": ["TestMode"]}'
```
Shape from the reference; values are placeholders [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-authenticated-request.html).

### 2.3 Diagnostics
Codes "resemble HTTP error codes" but are not HTTP codes; returned in authenticated responses and written to `PersonalizationLog` for unauthenticated calls [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-pipeline-diagnostics.html).

| Code | Name | Meaning / client effect |
|---|---|---|
| 200 / 201 | `OK` / `NO_DECISION_QUALIFIED` | normal / individual matched no decision |
| 401 | `POINT_NOT_CONFIGURED` | typo in `name`/`id`, wrong tenant endpoint, transient network (retry after 30 s), unsynced point (edit and re-save), conflicting IDs/names |
| 402 / 403 | `UNIDENTIFIED_POINT_REQUESTED` / `NO_POINTS_REQUEST` | point lacks `id` and `name` / no usable points left |
| 405 | `PERMISSION_DENIED` | CoPilot Action personalization requested unauthenticated or in a batch; Personalization not enabled |
| 406 | `TOO_MANY_REQUESTS` | internal; client gets HTTP `429` — throttle or hold off |
| 407 / 408 | `DECISION_NOT_FOUND` / `SPECIFIED_DECISION_NOT_SUPPORTED` | `decisionId` not on the point / `decisionId` on unauthenticated call → HTTP `400` |
| 421 / 431 | `PERSONALIZER_NOT_SELECTED` / `PERSONALIZER_TYPE_NOT_FOUND` | no qualifying decision or personalizer / point configuration problem |
| 500 / 501 | `UNEXPECTED_ERROR` / `INTERRUPTION` | log formatting error (empty `Content`) / low-level interruption, retry |
| 502 / 503 | `TIMEOUT` / `MODEL_LOOKUP_FAILURE` | internal; HTTP `503` "Timeout Exceeded" / "Failed to lookup tenant metadata" |
| 511 / 512 / 513 | `QUERY_SERVICE_ERROR` / `QUERY_SERVICE_MISSING_PROFILE` / `CANNOT_PARSE_PROFILE` | lookup failed (anonymous or HTTP `503`) / no profile data graph (anonymous) / unparseable profile |
| 521 / 522 / 523 | `RULE_EVALUATION_FAILURE` / `EXPERIMENT_EVALUATION_FAILURE` / `VALIDATION_ERROR_RULES_CONFIGURATION` | misconfigured rules or data-type mismatch / experiment error |
| 531 / 532 / 533 | `CONTENT_RETRIEVAL_ERROR_FROM_RECOMMENDATION_SERVICE` / `PERSONALIZER_RUNTIME_EXCEPTION` / `RECOMMENDER_CONTENT_SIZE_EXCEEDED` | recommendation service errors / response truncated to the item maximum |

### 2.4 Limits that bound server-side calls
All from "Limits for Salesforce Personalization" [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_basics_limits.htm&release=264.0.0&type=5):
- Recommenders: `60000` recommendation requests per minute per tenant; max `24` recommendations returned; full data refresh daily; `10` recommenders per org across data spaces (`1` objective-based with the Salesforce Personalization Card); `10` recommender objectives per org; `10` conditions per include/exclude filter.
- Points: `25` decisions per point; `50` targeting conditions per decision or experiment; `10` merge fields per decision.
- Batch: `20` active batch personalization jobs per org.
- Throttling surfaces as HTTP `429` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-pipeline-diagnostics.html). No documented decision-request rate limit, latency SLA, payload size or max points per request (gap).
- Each decision is billable (usage type `Personalization Decision`): Personalization Credits or Flex Credits per contract [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_basics_billable_usage_types.htm&release=264.0.0&type=5).

  1. Point with `Authentication Required`; authenticated endpoint + Data 360 token (§2.1).
  2. Real-time profile data graph (the invocable action has no `profile` input [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/get-personalization-decision-invocable-action-reference.html)), or a standard graph plus the full `profile` JSON (API callers only, §2.2).

  4. Persist `personalizationId`, `personalizationContentId` and `requestId` with the interaction; optionally send `correlationId` / `messageId` (measurement-and-attribution.md §1.6).
     - Send server-side view, click and outcome events with the Data 360 **Ingestion API**: streaming pattern, payload under 200 KB, check with Synchronous Record Validation first, then expect `202 Accepted` [src](https://developer.salesforce.com/docs/data/data-cloud-int/guide/c360-a-ingestion-api.html) [src](https://developer.salesforce.com/docs/data/data-cloud-int/references/data-cloud-ingestionapi-ref/c360-a-api-streaming-insert-example.html).      - No profile (anonymous caller, no JavaScript): send `executionFlags: ["ContextOnly"]` and decide on context; see web-sdk-and-sitemap.md §10.
  5. Fallback content for `201 NO_DECISION_QUALIFIED`, `511`/`512` (anonymous or HTTP 503), `502` (HTTP 503 "Timeout Exceeded"), HTTP 429 (back off) and `401` network causes (retry after 30 s) (§2.3).
  6. Remove `TestMode` in production; confirm which Individual ID a CRM record maps to (Data Explorer on Individual, filtered by the source record ID) before go-live.

## 3. Batch personalization decisions for segments
- Decisions for a Data 360 segment are saved to an output DMO, then sent via Data 360 DMO activation to e.g. MCE, GCP, Amazon S3, Azure (overview) — the Create article adds SFTP; EE/UE/PE/DE with Data 360 [src](https://help.salesforce.com/s/articleView?id=mktg.persn_batch_persn_decisions_for_customer_segments.htm&release=264.0.0&type=5), [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_batch_create_batch_persnl.htm&release=264.0.0&type=5).
- Setup: permissions `Personalization Batch Decision` + `Market Segment Definitions`; `App Launcher` → `Batch Personalizations` → `New` [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_batch_create_batch_persnl.htm&release=264.0.0&type=5):
  1. Data space (drives the segment list).
  2. Target segment on Individual or Unified Individual; UI-rooted segments list only points whose data graph uses the same UI object.
  3. Personalization point; with a UI-rooted data graph only one underlying individual ID per unified individual is decided (avoids duplicate credits).
  4. Optional contact point filter (≥1 selected contact point; options come from contact point DMOs on the profile data graph).
  5. Name → auto API name, output DMO label and name.
  6. Schedule = the segment's publish schedule (`1hr`, `4hrs`, `12hrs`, `24hrs`, no refresh); change it on the segment.
  7. Refresh type `Full` | `Incremental` (only members added since the last run).
  8. Optional `DMO Activation Trigger` (does not create the activation).
  9. Active or paused; active jobs run on segment refresh or via `Run Batch Personalization`.
- Output DMO (API name from the batch name; PK `Id__c`): `ProfileID__c` (UI ID if available, else individual ID), `IndividualId__c`, `KQ_Id__c`, `SegmentId__c`, `PersonalizationPointId__c`, `PersonalizationPointApiName__c`, `PersonalizationDecisionId__c`, `PersonalizationBatchDecisionId__c`, `PersonalizationId__c`, `LastUpdatedDateTime__c`, `ActivationData__c` (JSON shaped like a decision response), `UnifiedIndividualId__c` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/batch-personalization-output-dmo.html).
- Activation (Data 360): Activations → `New` → `Data Model Object (DMO)` → `Batch` → data space → output DMO → activation target → optional contact points → `Activation Membership` filters → `Contact Points` filters (consent: `Contact Point Consent` L3, `Contact Point Subscription Consent` L4) → add attributes → name → refresh `Full` | `Incremental` → `Save` → `Publish Now`. Permission: `Data Cloud Architect`, `Data Cloud Activation Manager` or `Data Cloud Activation Specialist`. PK/FK fields aren't offered as extra attributes; copy them with a formula field if the destination needs them [src](https://help.salesforce.com/s/articleView?id=data.c360_a_batch_dmo_activation.htm&release=264.0.0&type=5). For batch output, include all output attributes [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_batch_create_dmo_activation_against_output_dmo.htm&release=264.0.0&type=5).
- Scheduling: batch DMO activations have no custom schedule in the UI [src](https://help.salesforce.com/s/articleView?id=data.c360_a_dmo_activation.htm&release=264.0.0&type=5). Cadence = segment publish schedule → batch job → "Trigger linked DMO Activation" → activation [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_batch_persnl_faqs.htm&release=264.0.0&type=5). Sequencing with the send isn't documented; gate the MCE send on the data extension being refreshed.
- MCE target: Activation Targets → `New` → `Marketing Cloud Engagement` → name, data space → Marketing Cloud connection → business units; several BUs → publishes as a Shared Data Extension; the data-space step warns about records from different EIDs being merged [src](https://help.salesforce.com/s/articleView?id=data.c360_a_create_marketing_cloud_activation_target.htm&release=264.0.0&type=5).
- IDs: the output writes the decided `IndividualId__c` and `UnifiedIndividualId__c`; if the decided individual isn't the MCE recipient, "use the unified individual ID as the entry point" to look up the right ID in an MCE table [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_batch_persnl_faqs.htm&release=264.0.0&type=5). Align `<MCE_SUBSCRIBER_KEY>` with one of these IDs before the first send.
- MCE AMPscript: `AttributeValue("ActivationData")`, then `BuildRowsetFromJSON(@data, "$.['data'][*]", true)` (items) and `"$.['attributes'][*]"` (attributes, read via `name`/`value`); payload follows the point's content schema [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/batch-persnl-sample-templates.html).
- Behavior: 20 active jobs per org; output kept 30 days; all decisions logged for analytics/attribution [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_batch_create_batch_persnl.htm&release=264.0.0&type=5); failed job retried up to 3×, then fault code + error state until triggered manually; contact point filtering can make decisions (credits) fewer than segment members; the UI ID is written so MCE can resolve the right individual [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_batch_persnl_faqs.htm&release=264.0.0&type=5).

## MCP confusion traps
- **MCP** "Personalization Mobile SDKs" (iOS v1.5.0, Android v1.5.1; references under `/docs/marketing/personalization/references/`) deliver MCP mobile campaigns and feed MCP profiles — not the SP Personalization module [src](https://developer.salesforce.com/docs/marketing/personalization/guide/mobile-integration.html). **MCP** Event API must not be used for mobile app events [src](https://developer.salesforce.com/docs/marketing/personalization/guide/event-api.html).
- **MCP** server-side campaigns (Premium Edition; `channel: Server`; `/api2/authevent/{dataset}` with an MCP API token via Basic Auth) ≠ SP Decisioning API [src](https://developer.salesforce.com/docs/marketing/personalization/guide/server-side-campaigns-templates.html).
- **MCP** Open Time Email and triggered campaigns ≠ SP batch decisions or MC Next Dynamic Content [src](https://help.salesforce.com/s/articleView?id=mktg.mc_pers.htm&release=264.0.0&type=5).
- **MCP** "Personalization Data Action Element" (`Automate Data Sent for Personalization`, MCP Sales/Service Cloud managed package) *sends* CRM record data to an MCP dataset; it returns no decisions and ≠ SP `Get Personalization Decisions` [src](https://help.salesforce.com/s/articleView?id=mktg.mc_pers_salesforce_sales_service_cloud_mgd_pkg_automate_pers_action_element_add.htm&release=264.0.0&type=5).
- **MCP** Einstein Recipes / Einstein Decisions ≠ SP recommenders / personalization decisions [src](https://help.salesforce.com/s/articleView?id=mktg.mc_pers_machine_learning.htm&release=264.0.0&type=5).
- MCE "Einstein Email Recommendations" (breadcrumb `Engagement: Einstein and Analytics`) is a third product — neither SP nor MCP [src](https://help.salesforce.com/s/articleView?id=mktg.mc_pb_einstein_email_recommendations.htm&release=264.0.0&type=5).
- MobilePush in-app messages (MCE) ≠ SP mobile content zones; the Journey Decisioning agent (MCE) is not an SP feature even though it can call `Get Context` (§4.3).
- `MCP+` SKUs consume Personalization Credits (Flex Credits for Flex variants) for SP decisions — a licensing overlap, not product identity [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_basics_billable_usage_types.htm&release=264.0.0&type=5).
- Release-note IDs `rn_persnl_*` also cover **MCP** items; check the Product column of "Personalization Features Released by Month" [src](https://help.salesforce.com/s/articleView?id=release-notes.rn_salesforce_personalization_features_released_by_month.htm&release=260&type=5).

## Gaps and uncertainties
- Pro-code mobile `View`/`Click` tracking method names are not on the iOS/Android pro-code pages.
- Doc conflicts: banner API name `Salesforce_Banner` (dev docs) vs `Salesforce_Personalization_Banner` (Help); Help configures a `Dismiss Action` and says components must track dismiss, dev docs support only `View`/`Click` end-to-end.
- Signature/label inconsistencies: iOS signature `decisionsRequestContext:` vs parameter table and examples `context:`; Android pro-code `timeoutMs` described "in seconds" with value `10000L` (low-code page: milliseconds); `experimentsOverride` table `cohortId` vs examples `cohordId`; Flutter baseline Swift 5.7+ / Kotlin Gradle plugin 2.3.0 vs native low-code Swift 5.9+ / Kotlin 2.4+.
- Decisioning API: `EnableDiagnostics`, `profileId`, `customContextVariable` appear only on the unauthenticated page, while diagnostics are returned only to authenticated calls. Standard-graph profile JSON goes "in the context object" (Help) vs a top-level `profile` field (API reference).
- Targeting options are labeled `Always (No Rules)` / `All Rules Are Met` / `Any Rule Is Met` (Add a Decision) vs `Always (No Conditions)` / `All Conditions Are Met` / `Any Condition Is Met` (Create a Targeting Rule).
- Get Context: API name `PersonalizeContext` vs instruction text `createContextPersonalization`; pre-chat fields `Individual_ID`/`Connector_App_Source_Id` in setup steps vs `Individual_Id`/`AppSource_Id` in the code sample; editions differ between the action reference and SP Help.
- Batch: the Create article says `Batch Status` reflects only sync status; the FAQ says `Batch Status` defines "Active" and `Status` is sync status. Toggle named `DMO Activation Trigger` (Create) vs "Trigger linked DMO Activation" (FAQ).
- Agent engagement sample builds `attributes` from `event.detail` outside the listener — adapt before use.
- No documented Decisioning API request-rate limit (beyond recommendation requests/min), latency SLA, payload limit or max points per request; no server-side use-case guide; SP in MC Next journeys undocumented; Experiment Connect (Connect REST) resources not reviewed; AWAC package internals not public.

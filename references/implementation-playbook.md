# New Implementation Playbook

## Scope
- Read this file when starting a **new** Salesforce Personalization (SP) customer or use case: before estimating or writing a statement of work, and whenever you choose channels, integration methods or a build order. It is industry-, business-model- (B2C, B2B) and site-agnostic; every site-type or channel rule is written as a condition.
- SP is the Data 360–native product sold with Marketing Cloud Next. It is **not** Marketing Cloud Personalization (MCP, formerly Interaction Studio / Evergage); MCP concepts such as Einstein Recipes, campaign statistics, Gears, campaign template code, implicit consent and native frequency capping don't exist in SP. See [sp-vs-mcp.md](sp-vs-mcp.md).
- This file sequences and links; detail lives in the sibling references: setup and limits [platform-and-setup.md](platform-and-setup.md), web [web-sdk-and-sitemap.md](web-sdk-and-sitemap.md) and [sitemap-templates.md](sitemap-templates.md), decisioning [decisioning.md](decisioning.md), WPM and experiments [wpm-experiences-campaigns.md](wpm-experiences-campaigns.md), measurement [measurement-and-attribution.md](measurement-and-attribution.md), non-web channels [mobile-and-channels.md](mobile-and-channels.md), SQL [sql-cookbook.md](sql-cookbook.md), failures [troubleshooting.md](troubleshooting.md).
- Baseline: release 264 (Winter '27). Labels: `(Field-observed, undocumented)` = seen in implementations, absent from docs; `(inference)` / `(design pattern)` = reasoned from cited docs, not a documented feature; `(UNVERIFIED)` = not confirmed.
- Workflow: run discovery → fill the architecture tables → follow the setup sequence → pick use-case patterns → design measurement **before** building → run the go-live checklist.

## Discovery checklist
Ask these in the first workshops. Each answer changes a design decision later in this file.

### Business goals and KPIs
- Top three outcomes (revenue, conversion, lead capture, content engagement, self-service deflection, retention) and the KPI that proves each. The KPI decides the engagement signal, metric and attribution model you build (see Measurement design).
- Is there a commerce flow with product browse, cart and order events? Predefined attribution needs Product Browse, Shopping Cart and Product Order Engagement [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_analytics_attribution_settings.htm&release=264.0.0&type=5). Without it (lead-gen, media, B2B, service), plan custom attribution.
- Traffic per page type, screen and audience: experiments need at least 1,000 participants per cohort [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_exp_considerations.htm&release=264.0.0&type=5), so low-traffic slots can't be A/B tested quickly.
- Who authors content and rules: marketers without code (WPM, Personalization Campaigns, low-code mobile) or developers (`fetch`, Decisioning API, pro-code mobile)?
- First use case (minimum viable scope), launch date and success threshold.

### Channels and site types
- **Multi-page or server-rendered web**: page types with URL patterns or DOM signals; can the site team add stable, empty placeholder elements with an `id` or `data-*` hook per slot?
- **SPA (client-side routing)**: which router; do route changes happen without page loads?
- **Framework-rendered components (React, Angular, Vue, other)**: can developers register Content Zone Handlers in components [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/integrate-personalization-modern-frontend-frameworks.html)?
- **Experience Cloud sites**: Aura or enhanced LWR? Build Your Own template? Can the site CSP be set to Relaxed and the SDK URL added to Trusted URLs? Is Agentforce Orchestrator (additional cost, authenticated users) in scope? Which consent manager feeds `updateConsents` (Aura, Web SDK) or `set-consent` (enhanced LWR)? Paths: Architecture decisions → Experience Cloud sites.
- **Headless front ends, kiosks, signage**: which backend calls the Decisioning API, and can it hold a Data 360 access token for the authenticated endpoint [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-authenticated-request.html)?
- **Native apps**: iOS, Android, React Native or Flutter; release cadence (low-code mobile lets business users publish "without writing code or shipping an app update" [src](https://help.salesforce.com/s/articleView?id=release-notes.rn_persnl_personalize_mobile_lowcode.htm&release=264.0.0&type=5)); is the Engagement Mobile SDK already embedded?
- **Salesforce apps and contact center**: Service Console, record pages or Flow (`Get Personalization Decisions` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/show-personalized-recommendations-in-flows.html)), or a third-party platform (Decisioning API)?
- **Email and other outbound**: Marketing Cloud Next (Dynamic Content is SP-backed [src](https://help.salesforce.com/s/articleView?id=mktg.mktg_content_personalization_ep.htm&release=264.0.0&type=5)), Marketing Cloud Engagement or another sender (batch decisions plus DMO activation [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_batch_create_batch_persnl.htm&release=264.0.0&type=5))?
- **Conversational**: is an Agentforce Service Agent with Enhanced Chat planned [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_agentforce_enable_personalization_agent.htm&release=264.0.0&type=5)?

### Site platform and tag management (web only)
- CMS or commerce platform, hosting and Content Security Policy: the page loads the connector's CDN script and calls the tenant endpoint (`POST https://<TENANT_ENDPOINT>/personalization/decisions`) [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-request-personalization.html).
- Domains and subdomains: `cookieDomain` defaults to the current domain, so cross-subdomain identity needs the parent domain in `init` [src](https://developer.salesforce.com/docs/data/salesforce-interactions-sdk/guide/c360a-api-initialization.html).
- Tag manager: SP docs place the SDK `<script>` in `<head>` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/integrate-salesforce-interactions-sdk.html). Data 360 documents a Google Tag Manager publication option only for the GA4 website connector [src](https://developer.salesforce.com/docs/data/data-cloud-int/guide/c360-a-web-connector-ga4.html); tag-manager loading for SP is undocumented, so test flicker defense and first-page decisions before accepting it.
- Who owns sitemap code, its repository and release process? The sitemap is uploaded on the website connector and replaced with **Upload | Replace Sitemap** [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_qs_configure_website_connector.htm&release=264.0.0&type=5).
- Is an MCP (`Evergage`) tag already on the site? Running both needs coexistence (MCP-breadcrumb page, cited for coexistence only) [src](https://help.salesforce.com/s/articleView?id=mktg.mc_pers_mcn_for_pers_requirements.htm&release=264.0.0&type=5).

### Consent (any consent platform)
- Which consent management platform (CMP), which categories, and which event or API exposes the visitor's choice (synchronous read, async callback, or both)?
- Web: the SDK stores and sends nothing until it receives `Opt In`, and `consents` is required in `init` [src](https://developer.salesforce.com/docs/data/salesforce-interactions-sdk/guide/c360a-api-consent.html) [src](https://developer.salesforce.com/docs/data/salesforce-interactions-sdk/guide/c360a-api-initialization.html). The only documented purpose is `Tracking` [src](https://developer.salesforce.com/docs/data/salesforce-interactions-sdk/guide/c360a-api-consent-data.html).
- Which CMP category legally covers behavioral personalization? Mapping `Opt In` to an always-on "strictly necessary" category opts everyone in; get privacy sign-off on the mapping.
- Mobile: the Engagement Mobile SDK defaults to `pending` and transmits only after `optIn` [src](https://developer.salesforce.com/docs/data/data-cloud-engagement-mobile-sdk/guide/c360a-api-engagement-mobile-sdk-consent-management-v3.html); where is the in-app consent prompt?
- Server-side, Flow and batch: whether these decisions honor Data 360 consent is undocumented; decide who filters non-consented people (for example in the batch segment) (inference).

### Identity
- Share of anonymous vs signed-in traffic; login mechanism; is a stable identifier available in the browser or app after login?
- Which identifier (CRM ID, customer or member number, account-holder ID, other) goes into `partyIdentification`, and does the identity resolution ruleset match it? SP's real-time rule matches Party Identification `Identification Number` with `Exact` and `Match on Blank` off [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_real_time_identity_resolution_for_einstein_personalization.htm&release=264.0.0&type=5).
- Could placeholder values reach identifier fields? Default values (the doc's example is `000-0000`) are a named cause of oversized unified profiles, identity resolution can't combine more than 50,000 records into one profile, and a literal `"null"` Identification Number is skipped during matching [src](https://help.salesforce.com/s/articleView?id=data.c360_a_resolution_troubleshooting_ir_errors.htm&release=264.0.0&type=5).
- Shared or public devices (kiosks, family tablets, agent desktops)? What happens on logout?
- Must web and app identities converge on one unified profile? B2B: is the decision subject a person (contact, lead) or an account?

### Data already in Data 360
- Data spaces in use; data streams (CRM, commerce, loyalty, subscriptions, content); DLO→DMO mappings; identity resolution rulesets and whether real-time matching is on.
- Catalog location: documented item data graph roots are Goods Product, Knowledge Article Version and Promotion [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_data_graphs_using.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_item_dg_for_max_clicks.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_item_dg_for_max_rev_with_prom.htm&release=264.0.0&type=5); other items (services, plans, offers, courses) need a custom DMO and a custom objective.
- Existing calculated insights, standard and real-time segments, and data graphs (25 per org, hard limit) [src](https://help.salesforce.com/s/articleView?id=data.c360_a_limits_and_guidelines.htm&release=264.0.0&type=5).
- Does the target data space already contain a profile data graph? If yes, `Use Case Setup` can't deploy there [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_use_case_wtk.htm&release=264.0.0&type=5).

### Licensing and credits
- Personalization License (50 million credits, 20 attribution models) or Personalization Card (1 million credits, 2 models; standalone Card isn't for web or mobile) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_basics_standard_editions_and_licenses.htm&release=264.0.0&type=5); the Card allows 1 objective-based recommender [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_basics_limits.htm&release=264.0.0&type=5).
- Every `Personalization Decision` is billable, in Personalization or Flex credits, tracked in Digital Wallet [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_basics_billable_usage_types.htm&release=264.0.0&type=5). Estimate monthly decisions as requests × points per request, per channel (inference).
- Data 360 consumption: real-time pipeline events and unique real-time profiles per billing month [src](https://help.salesforce.com/s/articleView?id=data.c360_a_billing_considerations_for_data_graphs.htm&release=264.0.0&type=5); calculated insights, including the two SP daily insights, are billable [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_install_pers_pipeline_dashboard.htm&release=264.0.0&type=5); sandbox usage consumes production credits [src](https://help.salesforce.com/s/articleView?id=data.c360_a_data_cloud_sandbox.htm&release=264.0.0&type=5).
- Add-ons: extra data spaces need an add-on license [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_data_space_requirements.htm&release=264.0.0&type=5); Pipeline Intelligence needs CRM Analytics [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_install_pers_pipeline_dashboard.htm&release=264.0.0&type=5); recommender data in Marketing Cloud Next email needs Marketing Cloud Next Advanced with Personalization Decision Credits [src](https://help.salesforce.com/s/articleView?id=mktg.mktg_content_personalization_data_sources.htm&release=264.0.0&type=5).

### Org, data spaces and environments
- Which org hosts Data 360 and SP; one data space or several (per brand, region or business unit)? A data space prefix is immutable after save [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/integrate-salesforce-interactions-sdk.html), and a point belongs to exactly one data space [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_considerations.htm&release=264.0.0&type=5).
- Sandboxes: Data 360 provisions only metadata; no data is replicated, even to Partial or Full Copy sandboxes; creating one needs `Data Cloud Architect`; replicated connections start `Inactive` and must be re-authorized [src](https://help.salesforce.com/s/articleView?id=data.c360_a_data_cloud_sandbox_create.htm&release=264.0.0&type=5). Web SDK and Mobile SDK connectors, data graphs, identity resolution and real-time segments are replicated and deployable; deploy with a DevOps data kit and a change set [src](https://help.salesforce.com/s/articleView?id=data.c360_a_data_cloud_sandbox.htm&release=264.0.0&type=5). Recommenders, engagement signals and objectives are packageable in data kits [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_including_components_in_data_kits.htm&release=264.0.0&type=5). WPM on a sandbox needs `&sf_personalization_wpm_env=prod_sandbox` [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_wpm_access_web_personalization_manager.htm&release=264.0.0&type=5).
- Which staging site or test app build maps to which org, and does it load that org's connector script (inference)?
- Who gets `Personalization Admin` vs `Personalization User`, and who needs `Data Cloud Architect`?

### Privacy and legal constraints
- Legal basis per region; regulated content categories (health, finance, minors) that must not be targeted.
- Data subject rights: submit every request through the Consent API; with identity resolution, submit for source individual profiles [src](https://help.salesforce.com/s/articleView?id=data.c360_a_data_subject_rights.htm&release=264.0.0&type=5). Deletion removes the Individual record, DMOs directly related through the Individual ID, their mapped DLOs and related calculated insights, not unrelated DMOs; it typically runs within hours, is reprocessed after 30, 60 and 90 days, and must also be submitted in every connected system [src](https://help.salesforce.com/s/articleView?id=data.c360_a_data_deletion_request.htm&release=264.0.0&type=5). Check whether custom engagement DMOs relate to the Individual.
- PII in web events and personalized URLs; data residency; retention (batch output is kept 30 days [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_batch_create_batch_persnl.htm&release=264.0.0&type=5)).
- AI disclosure: objective-based recommenders don't use demographic data or data purchased from third parties [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_machine_learning_for_objective_based_recommenders.htm&release=264.0.0&type=5).

## Architecture decisions

### Channel → integration method
| Channel or site type | Integration method | Profile data graph | Placement and rendering | Key constraint |
|---|---|---|---|---|
| Multi-page / server-rendered web | Web SDK + sitemap + WPM experiences | Real-time | WPM `Replace an Element` on a stable hook, or a content zone | WPM lists only real-time points in the sitemap's data space [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_wpm_use_predefined_templates.htm&release=264.0.0&type=5) |
| SPA (virtual navigation) | Same, plus `reinit()` on route change | Real-time | As above; handlers if framework-rendered | `reinit()` re-runs sitemap evaluation [src](https://developer.salesforce.com/docs/data/salesforce-interactions-sdk/guide/c360a-api-initialization.html) |
| Framework-rendered components | Content Zone Handler registered in the component | Real-time | WPM `Use Content Zone Handler` | SDK DOM changes can make content disappear [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/integrate-personalization-modern-frontend-frameworks.html) |
| Headless web, kiosk, signage | `SalesforceInteractions.Personalization.fetch()` or Decisioning API | Real-time (or standard + caller-supplied profile) | Your code renders and sends view/click events | You own rendering, tracking and flicker [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/track-personalization-engagement.html) |
| Native app, marketer-editable | Low-code `ContentZone` + registered components | Real-time (recommended) | Mobile content zones, built-in or custom components | Only `View`/`Click` end-to-end [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-android.html) |
| Native app, custom UI | Pro-code `fetchDecisions` | Real-time (recommended) | App renders; manual tracking | Caller groups points by data graph [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-android.html) |
| Salesforce console, record page, Flow | `Get Personalization Decisions` invocable action | Real-time or standard | Screen flow / Lightning component | Needs the Personalization license [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/get-personalization-decision-invocable-action-reference.html) |
| External server (contact center, kiosk backend, SSR, render service) | Authenticated Decisioning API | Real-time, or standard with `profile` | Caller renders | Diagnostics only on authenticated calls [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-pipeline-diagnostics.html) |
| Marketing Cloud Next email / landing page | Dynamic Content variations, `Personalization Recommender` data source | Standard (profile supplied automatically) | Email components, repeaters | 25 points per email or landing page, 15 variations per component [src](https://help.salesforce.com/s/articleView?id=mktg.mktg_content_personalization_ep.htm&release=264.0.0&type=5) |
| Outbound to any sender | Batch personalization for a segment → output DMO → DMO activation | Standard (profile supplied automatically) | Sender renders `ActivationData` JSON | 20 active jobs per org [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_batch_create_batch_persnl.htm&release=264.0.0&type=5) |
| No website at all | API, mobile, Flow, batch only | Per row above | No WPM (WPM needs the Web SDK [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_web_personalization_manager.htm&release=264.0.0&type=5)) | Plan engagement ingestion per channel |
| Experience Cloud site | Aura: Web SDK in header markup; enhanced LWR: native Data Cloud integration; Agentforce Orchestrator referencing SP points | Per path (below) | Orchestrator greetings, prompts and CTA; WPM undocumented | Pick by runtime and template (below) |

Real-time graphs are recommended for latency-sensitive channels such as web and mobile; standard graphs for outbound and batch [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_standard_profile_data_graphs.htm&release=264.0.0&type=5).

### Experience Cloud sites
- **Aura (Web SDK):** website connector → **Upload Files** with the custom `Aura_Sites_Schema.json` → **Sitemap** tab → **Upload Sitemap** with `aura_sitemap.js` → web data stream with the `Party Identification`, `Identity`, `Search` and `UserEngagement` events → map with the starter web and mobile connector mappings → Setup → **Trusted URLs** → the connector's SDK URL with CSP directives `connect-src` and `img-src` → Experience Builder → **Settings** → **Advanced** → **Edit Header Markup** → paste the init script → **Security & Privacy** → **Relaxed CSP: Permit Access to Inline Scripts and Allowed Hosts** [src](https://help.salesforce.com/s/articleView?id=experience.set_up_event_ingestion_for_experience_cloud_sites.htm&release=264.0.0&type=5). The page's snippet hard-codes `ConsentStatus.OptIn`; feed `consents` from the consent manager instead ([web-sdk-and-sitemap.md](web-sdk-and-sitemap.md) §3).
- **Enhanced LWR (native integration):** Experience Builder → **Settings** → **Integrations** → Data Cloud card → **Add to Site** → **Share site data with Data Cloud**, then publish after the confirmation email. The data space can't be changed later (delete and reconfigure the integration), and setup can take up to an hour; interaction events are mapped automatically [src](https://help.salesforce.com/s/articleView?id=experience.exp_cloud_data_cloud.htm&release=264.0.0&type=5). Experience Tag Manager "is installed automatically" [src](https://developer.salesforce.com/docs/atlas.en-us.exp_cloud_lwr.meta/exp_cloud_lwr/data_capture.htm).
  - Consent: "User consent is turned off by default for Experience Cloud sites" [src](https://help.salesforce.com/s/articleView?id=experience.exp_cloud_data_cloud.htm&release=264.0.0&type=5). Tag Manager listens for an `experience_interaction` event named `set-consent`; resend it on every page load; `set-consent` without a `value` removes consent; add it via Relaxed CSP and **Edit Head Markup**. The doc's first snippet sends `value: true` for everyone; pass the CMP's decision instead [src](https://developer.salesforce.com/docs/atlas.en-us.exp_cloud_lwr.meta/exp_cloud_lwr/data_cloud_consent_management.htm).
- **Agentforce Orchestrator** (Aura or LWR sites on the Build Your Own template, authenticated users, additional cost): admins "configure personalization points in Salesforce Personalization and reference them in Agentforce Orchestrator configurations" for AI greetings, suggested prompts and a primary CTA [src](https://help.salesforce.com/s/articleView?id=release-notes.rn_deliver_personalized_recommendations_to_your_experience_cloud_site_users.htm&release=262.0.0&type=5). Setup → **Agentforce Orchestrator** → **New** → type **Self-Service** → Greeting Settings (`Greeting Prompt Lookup`, `Greeting Profile Data Graph`) → **Recommendation Settings**: select the personalization point [src](https://help.salesforce.com/s/articleView?id=experience.set_up_agentforce_orchestrator_configurations.htm&release=264.0.0&type=5).
- Undocumented: WPM on Experience Cloud (WPM is documented for "non-Salesforce websites" [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_web_personalization_manager.htm&release=264.0.0&type=5)); SP `Personalization` module rendering (`fetch`, content zones) on Aura or through Tag Manager on enhanced LWR (UNVERIFIED); `Get Personalization Decisions` for external site users; whether the Card or the License covers Experience Cloud sites.

### Profile data graph type and root
| Choice | Use when | Consequence |
|---|---|---|
| Real-time graph | Web, mobile, WPM, in-session rules, real-time segments, insights, affinities | SP calls the profile API per request [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_real_time_profile_data_graphs.htm&release=264.0.0&type=5); new graphs allow only 1:1 and 1:N joins on the parent primary key [src](https://help.salesforce.com/s/articleView?id=data.c360_a_create_a_data_graph.htm&release=264.0.0&type=5) |
| Standard graph | Batch, Marketing Cloud Next sends, servers that send the profile | Without a supplied profile, profile-based rules and recommender filters evaluate false [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_standard_profile_data_graphs.htm&release=264.0.0&type=5) |
| Root `Unified Individual` | Default when identity resolution unifies people (B2C or B2B contacts) | Needed for real-time identity resolution [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_qs_add_recommended_rules_to_ir_ruleset.htm&release=264.0.0&type=5) |
| Root `Individual` | No identity resolution, or Individual-rooted batch segments | Batch on Individual-rooted segments allows any point [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_batch_create_batch_persnl.htm&release=264.0.0&type=5) |
| Root `Account` | B2B account-level recommendations | Rule-based recommenders only [src](https://help.salesforce.com/s/articleView?id=release-notes.rn_persnl_tailor_recommendations_for_accounts.htm&release=262.0.0&type=5); requests send `profileId` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-request-personalization.html); real-time segmentation doesn't run with Account and Individual in one graph [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_segments_using.htm&release=264.0.0&type=5) |

- One request can only contain points that share a profile data graph [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-request-personalization.html); keep one real-time graph per data space for web unless a channel truly needs another.
- Keep real-time graphs lean: 200 KB guidance, 25 objects, 30-day engagement age [src](https://help.salesforce.com/s/articleView?id=data.c360_a_limits_and_guidelines.htm&release=264.0.0&type=5). Keep record caching on so a known visitor's first page personalizes [src](https://help.salesforce.com/s/articleView?id=data.c360_a_record_caching_in_rt_data_graphs.htm&release=264.0.0&type=5).

### Placement options (web only)
| Option | Best for | Avoid when |
|---|---|---|
| WPM `Replace an Element` / `Add Before an Element` / `Add After an Element` | Pages with a stable `id` or `data-*` hook | Target exists only in some user states or is re-rendered by a framework |
| Sitemap content zone + `Replace a Content Zone` | Developer-owned, named slots reused across page types [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/set-up-content-zones.html) | The same element is also targeted by a WPM element experience (two placement paths) |
| `Use Content Zone Handler` | Framework-rendered components; handing data to your own renderer [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/integrate-personalization-modern-frontend-frameworks.html) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_point_decision_display_seg_membership_in_merge_fields.htm&release=264.0.0&type=5) | No developer capacity to register and reset handlers |
| `Add an Overlay` (`Immediately`, `Exit Intent`, `Element Click`, `Scroll Percentage`) | Pop-ups, exit intent, click-triggered panels [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_wpm_use_predefined_templates.htm&release=264.0.0&type=5) | Touch-first traffic, where cursor-based exit intent may not fire (inference) |
| `Select and Modify Existing Elements` | Quick text, URL, image swaps [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_wpm_manually_personalize_page_elements.htm&release=264.0.0&type=5) | Layouts or recommendation lists (use templates) |
| `Personalization.fetch()` + own rendering | Fully custom UI, headless | You must send `personalization-view`/`-click` with both IDs [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/track-personalization-engagement.html) |

### Site-type considerations
- **If the site is multi-page or server-rendered**, every full page load runs `init` and the sitemap again; `reinit()` is documented only for virtual navigation, so no reinit wiring is needed [src](https://developer.salesforce.com/docs/data/salesforce-interactions-sdk/guide/c360a-api-initialization.html). Start from the multi-page starter in [sitemap-templates.md](sitemap-templates.md) §2. Match page types on URL path or stable DOM markers. Test back/forward-cache restores for duplicate renders (Field-observed, undocumented).
- **If the server should render the decision** (SSR, edge, no-flicker requirement), call the authenticated Decisioning API server-side and send view/click events from the page with the returned IDs (inference; token handling stays on the server).
- **If the site is an SPA**, call `reinit()` on virtual navigation; the docs' baseline polls `window.location.href` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/example-sitemap.html) (optional add-on: [sitemap-templates.md](sitemap-templates.md) §4). Hardening (Field-observed, undocumented): wait for the new route's DOM, cap the wait, never run concurrently, make one-time patches idempotent.
- **If components are rendered by a framework**, register `SalesforceInteractions.Personalization.Config.ContentZoneHandler.set(name, { onReady, onRevert, path })`, render original children when no content arrives, and reset the handler on unmount [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/integrate-personalization-modern-frontend-frameworks.html). Keep one placement path per slot.
- **If there is no website**, skip the website connector, sitemap and WPM; use the Decisioning API, Flow, mobile SDK or batch, and design how engagement events reach Data 360 for measurement.
- Page type `name` values are contracts: they bind WPM `Current Page Type` and become `sourcePageType` on events [src](https://developer.salesforce.com/docs/data/salesforce-interactions-sdk/guide/c360a-api-translating-sdk-events-to-web-connector-schemas.html). Agree names in discovery and don't rename them.

### Decision record (write it down before building)
| Decision | Record | Why it's hard to change later |
|---|---|---|
| Data space(s) and prefix | Name, prefix, which brands or regions | Prefix is immutable; points bind to one data space |
| Profile data graph(s) | Type, root, objects, record caching on/off | Points and recommenders are tied to their graph |
| `Use Case Setup` yes/no | Target data space | Blocked once a profile graph exists there |
| Page type names (web) | Final list of `pageTypes[].name` | WPM bindings and report dimensions |
| Placement per slot | Element hook, content zone name or handler name | Two paths per slot duplicate renders |
| Consent mapping | CMP category → `Tracking` (web), `optIn` trigger (mobile) | Legal sign-off |
| Known-user identifier | `IDName`, `IDType`, source of `userId` | Must equal the match rule |
| Content schema attributes | Developer names per schema | Renderers key on them |
| Measurement | Signals, metrics, models, windows | Model slots (20 per org) include inactive models |

## Use-case patterns

| # | Pattern | Type | Graph | Typical delivery | Primary measurement |
|---|---|---|---|---|---|
| 1 | Segment-based content slot | Dynamic Content | Real-time | WPM element, handler, app zone | View→click funnel, SQL CTR |
| 2 | Product recommendations | Recommendations | Real-time | WPM template, app zone | Predefined attribution |
| 3 | Content/article recommendations | Recommendations | Real-time | WPM template or handler | Click signal, experiment |
| 4 | Infobar, pop-up, exit intent (web) | Dynamic Content | Real-time | WPM overlay | View/click/dismiss |
| 5 | Anonymous by UTM/source/page type | Dynamic Content | Real-time | WPM, API with `requestUrl` | Custom attribution |
| 6 | Known by tier, plan or insight | Either | Real-time | WPM, handler, app | Experiment |
| 7 | B2B account-based | Recommendations (rule-based) | Account root | Flow action, API | Click signal, CRM outcomes |
| 8 | Server-side next-best-offer | Either | Real-time or standard | Authenticated API, Flow | Ingested accept/decline |
| 9 | Native mobile in-app | Either | Real-time | Low-code or pro-code SDK | Built-in View/Click |
| 10 | Batch for email/outbound | Either | Standard | Batch + activation | Email clicks |
| 11 | A/B testing | Any point | Point's graph | Unchanged | Bayesian experiment |
| 12 | Frequency capping (design pattern) | Rule pattern | Real-time | Unchanged | Cap hit rate via SQL |

### 1. Segment-based content slot (hero, banner, CTA, message)
- **When:** a known audience (segment) should see different creative or copy in one slot, on web or app.
- **SP objects:** Dynamic Content schema (for example header, sub-header, image URL, CTA text, CTA URL), point on the real-time graph, one decision per segment plus a catch-all, experience template.
- **Data:** segment on the graph root; real-time segment for in-session membership (add segment ID + timestamp) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_segments_using.htm&release=264.0.0&type=5).
- **Delivery:** web multi-page: WPM `Replace an Element` on `#<placeholder-id>`; framework site: handler; app: mobile content zone.
- **Measure:** `personalization-view` → `personalization-click` custom attribution, signals filtered by point through the Personalization Log; CTR from SQL.
- **Pitfalls:** standard segments refresh on a schedule; image creative that already contains text renders a "banner in a banner" (Field-observed, undocumented).

### 2. Product recommendations (home, product detail, cart)
- **When:** a commerce catalog with browse and order history.
- **SP objects:** Recommendations schema on a Goods Product item graph; objective-based `Maximize Revenue` (home, generic) or rule-based co-bought with a `Decision Context` filter (product detail, cart) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_filters_configure_multiple_dimension_example.htm&release=264.0.0&type=5); fallback recommender.
- **Data:** catalog fields, Product Sales insight, browse/cart/order engagement; objective-based needs at least 3 engagement activities [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_considerations.htm&release=264.0.0&type=5).
- **Delivery:** WPM template with a loop over items (helper syntax UNVERIFIED; see [wpm-experiences-campaigns.md](wpm-experiences-campaigns.md)); on the web pass the viewed item as `anchorId`/`anchorType` through sitemap `contextualAttributes` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/set-up-dynamic-context-variables.html); in apps use the request context builder's anchor.
- **Measure:** engagement destination `Product Engagement` (`catalog` events); predefined attribution for carts, orders, revenue [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_analytics_attribution_settings.htm&release=264.0.0&type=5).
- **Pitfalls:** 10 recommenders per org [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_basics_limits.htm&release=264.0.0&type=5), so prefer dynamic context variables in filters over one recommender per category [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/set-up-dynamic-context-variables.html); exclude unsellable or expired items with filters [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_filters_operators.htm&release=264.0.0&type=5).

### 3. Content or article recommendations
- **When:** media, knowledge base, B2B resources, support deflection.
- **SP objects:** `Maximize Clicks` on a `Knowledge Article Version` item graph [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_item_dg_for_max_clicks.htm&release=264.0.0&type=5), or a custom objective over a custom content DMO with an engagement signal whose `Item Identifier` is the content ID [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_create_custom_objective.htm&release=264.0.0&type=5).
- **Data:** content metadata (titles, categories) powers cold start [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_dlpr_cold_start.htm&release=264.0.0&type=5); content view/click events.
- **Delivery:** WPM template or handler; `Maximize Article Clicks` via `Use Case Setup` if the data space has no profile graphs yet.
- **Measure:** click signal with the content ID; experiment against a rule-based "most viewed" control.
- **Pitfalls:** the `Product Engagement` destination sends `type: Product` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/track-personalization-engagement.html); for non-product items define a custom destination with the right `type` (inference).

### 4. Infobar, pop-up and exit-intent overlay (web)
- **When:** announcements, lead capture, form prompts, cart-abandon nudges.
- **SP objects:** Dynamic Content schema, point, decisions; experience template sized for an overlay.
- **Data:** optional segment, UTM or page-type rules.
- **Delivery:** WPM `Add an Overlay` with `Immediately`, `Exit Intent` (optional delay), `Element Click` or `Scroll Percentage`; selector-less global content zones (`global_popup`, `global_infobar`) are documented examples [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/set-up-content-zones.html).
- **Measure:** view and click signals; add a `Dismiss Action` in connector tracking if dismissals matter [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_mobile_engagement_tracking.htm&release=264.0.0&type=5).
- **Pitfalls:** no native frequency cap (see pattern 12); get consent and accessibility sign-off on modal overlays.

### 5. Anonymous visitors by UTM, source or page type (Visit Context)
- **When:** paid-media landing continuity, first-visit messaging, section-specific offers.
- **SP objects:** decisions using `UTM Parameters`, `Source`, `Visit Context`, `Scheduling` [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_targeting_rules_create.htm&release=264.0.0&type=5).
- **Data:** none beyond the request; the Web SDK sends `pageType`, `requestUrl` and `utm_*` automatically [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/set-up-dynamic-context-variables.html); servers send `requestUrl` for UTM parsing [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-request-personalization.html).
- **Delivery:** WPM with `Current Page Type` or `Page URL` wildcards; or any API channel.
- **Measure:** custom attribution; experiment per campaign landing.
- **Pitfalls:** UTM values sit only on the landing URL, so later pages lose them unless you persist them as profile or engagement data (inference). Visit Context depends on stable page type names.

### 6. Known people by tier, plan, subscription or calculated insight
- **When:** members, subscribers, account holders, signed-in B2B contacts.
- **SP objects:** decisions on `Direct Attributes`, `Related Attributes` or `Calculated Insights`; merge fields (max 10 per decision) with default text [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_point_decision_add_merge_fields.htm&release=264.0.0&type=5).
- **Data:** related profile data joined to Individual/Unified Individual by primary key (real-time joins) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_qs_create_required_data_graphs.htm&release=264.0.0&type=5); identity resolution; record caching.
- **Delivery:** WPM, handler or app zone; `partyIdentification` (web) or the mobile identity event sent at login.
- **Measure:** experiment tier-specific vs generic content; attribution by decision.
- **Pitfalls:** calculated insights are "not for real-time Personalization applications" [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_insights_using.htm&release=264.0.0&type=5); shared devices leak personal content unless you reset identity on logout.

### 7. B2B account-based personalization
- **When:** portals, partner sites, sales and service consoles.
- **SP objects:** profile graph rooted on `Account`, rule-based recommender over account attributes and account-level insights [src](https://help.salesforce.com/s/articleView?id=release-notes.rn_persnl_tailor_recommendations_for_accounts.htm&release=262.0.0&type=5).
- **Data:** account firmographics, account-level calculated insights, contact-to-account relationships.
- **Delivery:** `Get Personalization Decisions` in a screen flow or Lightning page; Decisioning API with `profileId` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-request-personalization.html).
- **Measure:** click signals; opportunity outcomes via CRM reporting.
- **Pitfalls:** objective-based recommenders on accounts aren't documented; don't mix Account and Individual in a graph that needs real-time segments [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_segments_using.htm&release=264.0.0&type=5); pulling account attributes into an Individual-rooted real-time graph needs an N:1 join, which new real-time graphs block [src](https://help.salesforce.com/s/articleView?id=data.c360_a_create_a_data_graph.htm&release=264.0.0&type=5) (inference); WPM on an account-rooted real-time graph (UNVERIFIED).

### 8. Next-best-offer server-side (contact center, kiosk, render service)
- **When:** an agent desktop, kiosk, SSR page or render service needs an offer at request time.
- **SP objects:** point with `Authentication Required`; decisions or a promotion/offer recommender [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_item_dg_for_max_rev_with_prom.htm&release=264.0.0&type=5).
- **Data:** individual ID the caller knows; optional `anchorId`, custom context variables (not recorded) [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-request-personalization.html).
- **Delivery:** Salesforce console → Flow action; external → authenticated API with the Data 360 token exchange [src](https://developer.salesforce.com/docs/data/data-cloud-dev/guide/dc-quick-start.html); on standard graphs send `profile`.
- **Measure:** ingest accept/decline as engagement events carrying the personalization IDs, for example through the Data 360 Ingestion API ([mobile-and-channels.md](mobile-and-channels.md) §2.5) (inference); `correlationId` links multiple requests [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-request-personalization.html).
- **Pitfalls:** SP doesn't enforce checkout rules such as minimum spend [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_recommender_example_filters_for_promotion_eligibility_criteria.htm&release=264.0.0&type=5); handle HTTP 429 with backoff [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-pipeline-diagnostics.html).

### 9. Native mobile in-app content
- **When:** app home banners, recommendation carousels, in-app messages.
- **SP objects:** points, mobile experience templates referencing components, mobile content zones.
- **Data:** Data 360 module events and identity; consent opt-in.
- **Delivery:** low-code `ContentZone` with built-in banner and recommendations components, or pro-code `fetchDecisions` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences.html).
- **Measure:** built-in components track View/Click; pro-code tracks manually.
- **Pitfalls:** low-code View fires on render, not verified visibility [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-flutter.html); a consent change doesn't retry a failed request [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-android.html).

### 10. Batch recommendations for email and outbound
- **When:** newsletters, triggered sends, files for external platforms.
- **SP objects:** point (often on a standard graph), batch personalization, output DMO, `Batch` activation.
- **Data:** Individual- or Unified Individual–rooted segment; optional contact point filter [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_batch_create_batch_persnl.htm&release=264.0.0&type=5).
- **Delivery:** activation to Marketing Cloud Engagement, cloud storage or SFTP; in Marketing Cloud Engagement parse `ActivationData` with AMPscript `BuildRowsetFromJSON` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/batch-persnl-sample-templates.html).
- **Measure:** email click events joined back to the output DMO's `PersonalizationId__c` (inference).
- **Pitfalls:** schedule follows the segment's publish schedule; 3 retries, then error state [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_batch_persnl_faqs.htm&release=264.0.0&type=5); if the sender is Marketing Cloud Next, prefer its native Dynamic Content.

### 11. A/B testing experiences
- **When:** proving lift before full rollout.
- **SP objects:** experiment on a point: primary metric, optional targeting, control cohort or `Defer response to the Personalization Decisions`, variation cohorts [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_exp_create.htm&release=264.0.0&type=5).
- **Data:** an engagement signal metric (`COUNT`, `SUM`, `AVG` or `DISTINCT` [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_es_metrics_configure.htm&release=264.0.0&type=5)) whose signal and fields are on the point's profile graph.
- **Delivery:** unchanged; experiments run behind the same point and experience.
- **Measure:** Bayesian results: `Chance to beat control`, credible interval, Data Visualization tab [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_exp_analytics_data_viz_tab.htm&release=264.0.0&type=5).
- **Pitfalls:** 1,000 participants per cohort; functional settings lock after `Start` [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_exp_manage.htm&release=264.0.0&type=5); `Winner Found` is advice, and you switch traffic manually.

### 12. Frequency capping (design pattern, not a documented feature)
- **When:** limit how often one person sees an overlay or promotion. SP has no native frequency cap (MCP does).
- **Pattern (inference):** a real-time insight counts the person's view engagements over a relative time window, and the decision's rule is "count below N".
  - Overlays and pop-ups: add no catch-all on that point, so a capped visitor gets `NO_DECISION_QUALIFIED` and nothing renders ([decisioning.md](decisioning.md) §8.1).
  - Inline slots that must never be empty: end with a neutral, non-promotional catch-all instead.
- **Documented building blocks:** real-time insights run on a real-time data graph, support only `Sum`/`Count`, allow a `Relative DateTime` filter, and need `Data Cloud Architect` [src](https://help.salesforce.com/s/articleView?id=data.c360_a_create_real_time_insight.htm&release=264.0.0&type=5); Data 360's own example counts product clicks this way [src](https://help.salesforce.com/s/articleView?id=data.c360_a_insights.htm&release=264.0.0&type=5).
- **Scoping (inference):** Website Engagement has no point field [src](https://developer.salesforce.com/docs/data/data-cloud-dmo-mapping/guide/c360dm-website-engagement-dmo.html). To cap one web experience, give it a custom engagement destination with a unique `interaction-name` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/track-personalization-engagement.html) and filter the insight on it; update signals that expect the default names. For apps, filter on the mobile view event instead.
- **Pitfalls:** 20 real-time insights per org; engagement older than 30 days drops out of graphs [src](https://help.salesforce.com/s/articleView?id=data.c360_a_limits_and_guidelines.htm&release=264.0.0&type=5); validate in a sandbox that counts update in-session before committing it in a statement of work.

## Measurement design

| Goal | Use | Watch out for |
|---|---|---|
| Views, clicks, CTR, uniques per point or decision | Query Editor or calculated insight SQL ([sql-cookbook.md](sql-cookbook.md) Q1–Q6) | CI reports can't compute formulas; put CTR in SQL [src](https://help.salesforce.com/s/articleView?id=analytics.rd_dc_reports_calculated_insights_limits.htm&release=264.0.0&type=5) |
| View → click (→ conversion) funnel per placement, in people | Custom attribution, 2–4 stages, `First Touch` or `Last Touch` [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_analytics_attrib_config_custom_create.htm&release=264.0.0&type=5) | Entrance counts individuals, later stages count conversions in the window [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_analytics_pers_attrib_intelligence_using.htm&release=264.0.0&type=5); differs from raw CTR |
| Carts, orders, revenue from recommendations | Predefined attribution (7-day window) | Needs Product Browse, Shopping Cart, Product Order Engagement [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_analytics_attribution_settings.htm&release=264.0.0&type=5) |
| Which variant wins | Experiment with one primary metric | Bayesian; only the primary metric decides [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_exp_analytics_primary_metric_results.htm&release=264.0.0&type=5) |
| Business outcome metric (sum, average, distinct) | Engagement signal metrics (`COUNT`, `SUM`, `AVG`, `DISTINCT`) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_es_metrics_configure.htm&release=264.0.0&type=5) | Custom objectives accept only `COUNT` (and `SELECT` via API) |
| Rate metric in experiments or attribution | Compound metric: one COUNT `Divide By` another [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_es_compound_metrics_examples.htm&release=264.0.0&type=5) | Both metrics on the same signal |
| Pipeline health: requests, points, uniques per day | Pipeline Intelligence (CRM Analytics) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_analytics_types.htm&release=264.0.0&type=5) | No view/click data; the two daily insights must be scheduled |
| BI on attribution DMOs | Tableau via the Salesforce Data Cloud Connector [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_analytics_attrib_intelligence_using_tableau.htm&release=264.0.0&type=5) | Check real DMO names (prefixes) in Data Explorer |

### Required wiring for attribution
- **Web:** the event schema must carry `personalizationId` and `personalizationContentId` on `userEngagement`, and both must be mapped on the Website Engagement DMO. The standard relationship joins Website Engagement `PersonalizationContentId` to Personalization Log `Id` [src](https://developer.salesforce.com/docs/data/data-cloud-dmo-mapping/guide/c360dm-si-websiteengagementdmo-dmo.html); without it views and clicks can't be attributed. The SP mapping table documents these fields only for Product Browse Engagement, so add the Website Engagement mapping yourself [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/integrate-salesforce-interactions-sdk.html).
- A signal is usable as a funnel stage only with an active relationship to the Personalization Log DMO [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_analytics_attrib_config_custom_create.htm&release=264.0.0&type=5). Filter by point through that related DMO, and leave the flows checkbox off (related object fields are unsupported in flows) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_engagement_signals_configure.htm&release=264.0.0&type=5).
- **Manual events** (custom rendering, `fetch`, server and other channels) must send `personalization: { id, contentId }`, with `contentId` = `personalizationContentId` for an item, otherwise `personalizationId` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/track-personalization-engagement.html).
- `TestMode` decisions record nothing to the data lake [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/decisioning-api-request-personalization.html); exclude other QA traffic from KPIs by other means.

### Measurement plan per use case (fill before build)
- Primary KPI and its engagement signal (DMO, identifiers, filters), metric and aggregation.
- Attribution model type, window, stages and `Content Match`; inactive models count toward 20 per org [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_basics_limits.htm&release=264.0.0&type=5).
- Experiment or holdout design and expected time to 1,000 participants per cohort.
- The SQL check that validates the numbers (Q1 views vs clicks, Q9 orphan events) and who reviews it weekly.

## Gaps and uncertainties
- Not documented: tag-manager loading of the SP Web SDK; WPM and SP Personalization-module rendering on Experience Cloud; WPM on account-rooted graphs; objective-based recommenders for accounts; a native frequency-capping recipe; whether server-side, Flow and batch decisions honor Data 360 consent; per-request decision rate limits and latency SLA; the exact WPM disabled-state label.
- Design patterns and inferences to validate in a sandbox before committing them in a statement of work: frequency capping (pattern 12) and its custom-destination scoping, UTM persistence, server-rendered decisions with browser-side tracking, custom destinations for non-product items, email-click joins to batch output, and WPM or SP rendering on Experience Cloud pages.
- WPM permission naming conflicts between the access article (`Web Personalization Manager user permission set`) and the prerequisites article (`Personalization Admin` or `Personalization User`); check the target org.

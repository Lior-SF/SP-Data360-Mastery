# Web Personalization Manager, Experiences, Campaigns and Experimentation

## Scope
- Salesforce Personalization (SP) web delivery layer: Web Personalization Manager (WPM), experiences, experience templates, personalization campaigns, experiments, and how Agentforce Adaptive Websites relates to WPM. Not Marketing Cloud Personalization (MCP).
- Baseline: release 264.0.0. Authoritative: SP Help (`persnl_*`, breadcrumb "Salesforce Help|Docs|Salesforce Personalization"), `developer/einstein-personalization`, Salesforce Interactions SDK (Web SDK) and Connect REST references, release notes 260–264.
- Labels: "(workshop source)" = Salesforce partner workshop, secondary. "(third-party)" = non-Salesforce community guide, used only where official docs are silent. "(MCP)" = MCP page, cited for contrast only. "(Field-observed, undocumented)" = seen in a live implementation, not in docs. "(UNVERIFIED)" = not confirmed in docs.
- Out of scope: decision and recommender internals, sitemap event capture, Decisioning API payloads, low-code mobile setup.

## 1. Prerequisites, permissions, access

### Prerequisites and permissions
- WPM manages personalized content on non-Salesforce websites, using interaction data captured by the Web SDK [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_web_personalization_manager.htm&release=264.0.0&type=5).
- Required: the Web SDK with the Personalization module [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_websdk_ep_module.htm&release=264.0.0&type=5); configured personalization points; the `Personalization Admin` or `Personalization User` permission set; third-party cookies enabled in the browser [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_wpm_prerequisites.htm&release=264.0.0&type=5).
- Contradiction (docs disagree): the access article's "User Permissions Needed" table says "Web Personalization Manager user permission set" [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_wpm_access_web_personalization_manager.htm&release=264.0.0&type=5), while the prerequisites article says "Users need a Personalization Admin or Personalization User permission set to access Web Personalization Manager", and the SP permissions topic and standard permission sets page describe only those two sets plus Data 360 connector permissions [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_set_up_permissions_and_related_prerequisites.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_assign_standard_permission_sets_to_users.htm&release=264.0.0&type=5). A WPM-named set is mentioned only in that one table and isn't described anywhere else. Assign `Personalization Admin` or `Personalization User`; if access still fails, look for a WPM-named set in Setup → `Permission Sets` (same resolution as [platform-and-setup.md](platform-and-setup.md) §3).
- Both standard sets grant `Access Personalization Platform`, `Attribution Model User`, `Personalization Intelligence User`, `Use CRM Analytics Templated Apps`, and Read/Create/Edit/Delete/View All on `Experiments`, `Personalization Points`, `Personalization Recommenders`, `Content Schemas`, `Streaming App Data Connectors`. Only `Personalization Admin` gets `Modify All` and write access to engagement signals, compound metrics, attribution models, objectives, and batch decisions [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_setup_assign_standard_permission_sets_to_users.htm&release=264.0.0&type=5).
- Creating or editing experience templates requires `Personalization Admin` [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_template_create.htm&release=264.0.0&type=5). Configuring and mapping campaigns requires `Personalization User` [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_campaign_create.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_campaign_map.htm&release=264.0.0&type=5).
- SDK order: call `SalesforceInteractions.Personalization.Config.initialize(...)` before `SalesforceInteractions.init` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/initialize-einstein-personalization-module.html).
- Data space: WPM lists only personalization points in the data space configured in the website's sitemap [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_wpm_use_predefined_templates.htm&release=264.0.0&type=5). With several data spaces, set `SalesforceInteractions.init({ personalization: { dataspace } })`; if unset, `fetch` uses `default` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/request-personalization-through-sitemap.html).
- Real-time profile data graphs are recommended for latency-sensitive channels such as web and mobile [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_profile_data_graphs.htm&release=264.0.0&type=5). The points WPM offers "use a real-time profile data graph and are created in the same data space as your sitemap" [src](https://partnerworkshops.salesforce.com/workshops/salesforce-personalization/personalization-experiences.html) (workshop source).
- A point with `Authentication Required` is evaluated only through SP's authenticated Decisioning API endpoint [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_personalization_point_considerations.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_exp_example_personalization_point_configure.htm&release=264.0.0&type=5). Inference: don't set it on points served to anonymous visitors through WPM (UNVERIFIED).

### Access
```text
https://site.example/page?sf_personalization_wpm                                      # no existing params
https://site.example/page?x=1&sf_personalization_wpm                                  # params present
https://site.example/?sf_personalization_wpm&sf_personalization_wpm_env=prod_sandbox  # sandbox
javascript:SalesforceInteractions.Personalization.launchWpm()                         # bookmarklet URL
```
- Append the string on a Web SDK-enabled page and enter Salesforce credentials. If the login window doesn't open, disable the popup blocker and click `Log In` [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_wpm_access_web_personalization_manager.htm&release=264.0.0&type=5). - Only third-party cookies and popups are documented as browser requirements; there is no browser support matrix.
- Login flow: `Log in` → credentials → `Allow` in the "Allow Access" window → WPM toolbar at the top of the page [src](https://partnerworkshops.salesforce.com/workshops/salesforce-personalization/personalization-experiences.html) (workshop source).

## 3. Location: page option and display method

### Page option
- `Current Page Type`: every page of the type you're on; on a Product Detail Page type it "duplicates the experience on all product detail pages" [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_wpm_use_predefined_templates.htm&release=264.0.0&type=5).
- `Page URL`: a specific URL; wildcards allowed, for example `https://mysite.com/product/*.html` [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_wpm_use_predefined_templates.htm&release=264.0.0&type=5).
- Label drift: the segment example says "use **Page URL** or **Page Type**", and to target every page "use **URL Address** with a wildcard (for example, https://example.com/*)" [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_point_decision_display_seg_membership_in_merge_fields.htm&release=264.0.0&type=5).
- A page type is a sitemap `pageTypes[]` entry with a required, unique `name` and a required `isMatch: () => Boolean` [src](https://developer.salesforce.com/docs/data/salesforce-interactions-sdk/guide/c360a-api-sitemap.html). That `name` reaches Data 360 as `sourcePageType`, "the `pageType` of the matching configuration that triggered the event" [src](https://developer.salesforce.com/docs/data/salesforce-interactions-sdk/guide/c360a-api-translating-sdk-events-to-web-connector-schemas.html).
- The option renders as `Current Page Type (<pageTypes[].name>)` (Field-observed, undocumented). Inference: renaming a page type relabels events and can detach experiences bound to the old name (UNVERIFIED).

### Display methods (experience-template mode)
| Label | Semantics |
| --- | --- |
| `Replace a Content Zone` | Pick a predefined zone from `Content Zone`; the zone is replaced with the template output |
| `Use Content Zone Handler` | Pick a handler from `Content Zone Handler`; available only when the site uses a frontend framework with a registered handler |
| `Replace an Element` | Hover until highlighted, click; the element is replaced |
| `Add Before an Element` / `Add After an Element` | Template output is inserted before or after the clicked element |
| `Add an Overlay` | Content layered over the page. `When to Display`: `Immediately`; `Exit Intent` (cursor moves to top of screen; delay allowed); `Element Click` (`Select Element` picks the trigger); `Scroll Percentage` |

- Table source: [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_wpm_use_predefined_templates.htm&release=264.0.0&type=5). The segment example labels the handler option `Content Zone Handler` [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_point_decision_display_seg_membership_in_merge_fields.htm&release=264.0.0&type=5).
- Overlays: no frequency, "show once", dismiss or precedence setting is documented for web overlays [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_wpm_use_predefined_templates.htm&release=264.0.0&type=5). `Exit Intent` is cursor-based, so pair it with a `Scroll Percentage` or `Element Click` experience for touch devices (inference). For frequency, see decisioning.md §8.1.
- The workshop leaves `Replace an Element` as the method for a hero and uses `Add After an Element` on `DIV.product-detail` for recommendations [src](https://partnerworkshops.salesforce.com/workshops/salesforce-personalization/personalization-experiences.html) (workshop source).
- Manual mode has no display-method list; it uses `Page Element Selection` and per-element attribute mapping [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_wpm_manually_personalize_page_elements.htm&release=264.0.0&type=5).

### Content zones (sitemap)
```js
const config = {   // composite of the doc's global and pageTypes examples
  global: { contentZones: [{ name: "global_popup" }, { name: "global_footer", selector: "footer.global-footer" }] },
  pageTypes: [{ name: "home", isMatch: () => /^\/$/.test(window.location.pathname), interaction: { name: "Homepage" },
    contentZones: [{ name: "recommendations_1", selector: "section.product_recs" },
                   { name: "recommendations_2", selector: "div#customer-stories" }] }],
};
```
- Zones are defined globally or per page type and "are then made available to personalization experience developers via Web Personalization Manager (WPM)". `name`: String, required; `selector`: String, not required [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/set-up-content-zones.html).
- Contradiction: MCP-breadcrumb migration articles say that for SP, content zones "must have both a name and selector value defined" [src](https://help.salesforce.com/s/articleView?id=mktg.mc_pers_mcn_for_pers_sitemap_and_data_ingestion.htm&release=264.0.0&type=5) (MCP) [src](https://help.salesforce.com/s/articleView?id=mktg.mc_pers_mcn_for_pers_sitemap_mod_quicklook.htm&release=264.0.0&type=5) (MCP). Defining a `selector` satisfies both.
- Wording drift: the SP web experiences page says content zones "are defined in your site's HTML and referenced in personalization experiences" [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_web.htm&release=264.0.0&type=5).

### Content Zone Handler (framework-rendered components)
```js
SalesforceInteractions.Personalization.Config.ContentZoneHandler.set("<HANDLER_NAME>", {
  label: "<Label shown in WPM>",       // defaults to the handler name
  path: "<TARGET_SELECTOR>",           // design-time highlight selector; never combine with onHighlight
  onReady: (content, metadata) => { document.querySelector("<TARGET_SELECTOR>").innerHTML = content; },
  onRevert: (metadata) => { document.querySelector("<TARGET_SELECTOR>").innerHTML = ""; },
});
```
- Why: SDK DOM manipulation "can conflict with the virtual DOM or rendering strategies of modern frameworks, causing personalized content to disappear" [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/integrate-personalization-modern-frontend-frameworks.html).
- `onReady` is required. `onRevert` (recommended), `path`, and `onHighlight` are design-time only. Use `onHighlight` only when `path` can't work (for example Shadow DOM), and never define both. Names must be unique and machine-friendly; unregister or reset handlers on unmount [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/integrate-personalization-modern-frontend-frameworks.html).
- Handlers can be headless: the SP segment example registers `ContentZoneHandler.set("Export_Segments", { onReady: content => { window.sfdcSegments = JSON.parse(content) } })` and selects it with `Content Zone Handler` in WPM [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_point_decision_display_seg_membership_in_merge_fields.htm&release=264.0.0&type=5).

### Element selection and selectors
- `Select Element`: hover until highlighted, then click. `Select Parent`: selects the enclosing element. Tip: the `Page Element` field can be used "to add the CSS code for the elements or make changes to existing ones" [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_wpm_manually_personalize_page_elements.htm&release=264.0.0&type=5).
- The workshop shows `TAG.class` notation: selecting a banner yields `DIV.slide-overlay`; `Select Parent` twice yields `DIV.carousel-container` [src](https://partnerworkshops.salesforce.com/workshops/salesforce-personalization/personalization-experiences.html) (workshop source).
- The `Page Element` value behaves as a CSS selector (`.` = class, `#` = id). For `<div id="<TARGET_ID>">`, `#<TARGET_ID>` matched and `DIV.<TARGET_ID>` did not. The overlay label read `div#<TARGET_ID>`, and the SDK logged `{"transformerName":"<TEMPLATE_API_NAME>","tag":"DIV","path":"div#<TARGET_ID>"}` (Field-observed, undocumented).
- An "element must be present on page" check is not documented (UNVERIFIED). Inference: the target must exist on the page open in WPM when you select it.

## 4. Experience templates

### Concept, types, release
- "An HTML template that maps content schema fields to your site's front-end output" [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_web.htm&release=264.0.0&type=5). Templates turn raw decision data into variables such as product name or image URL [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_template.htm&release=264.0.0&type=5).
- Types: `Handlebars` (web HTML) and `Agent Script` (agentic experiences) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_template.htm&release=264.0.0&type=5). The workshop UI shows `Handlebars` / `AgentScript` in `Experience Template Type for Web` [src](https://partnerworkshops.salesforce.com/workshops/salesforce-personalization/experience-templates.html) (workshop source).
- Global templates are preconfigured blueprints (for example a hero banner) with recommended data mappings and Data 360 ingestion guidance; a global template "is for internal use" and speeds up building the experience template [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_template.htm&release=264.0.0&type=5). The workshop names `Simple Hero Banner` and `Simple Recommendations` [src](https://partnerworkshops.salesforce.com/workshops/salesforce-personalization/experience-templates.html) (workshop source).
- Building templates in the Personalization app arrived in May '26 (262 notes). "Salesforce automatically migrates any existing templates in your sitemap to experience templates"; if not, contact Support. Editions: Professional, Enterprise, Unlimited, Developer with the SP add-on [src](https://help.salesforce.com/s/articleView?id=release-notes.rn_persnl_build_customize_experience_templates.htm&release=262.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=release-notes.rn_salesforce_personalization_features_released_by_month.htm&release=262.0.0&type=5).

### Create (Personalization app → `Experience Templates` → `New`)
1. Properties: data space, channel `Web`, unique template name and API name [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_template_create.htm&release=264.0.0&type=5).
2. Connect to your site: choose websites (workshop list `Connected Websites`; one template can serve several website connectors) [src](https://partnerworkshops.salesforce.com/workshops/salesforce-personalization/experience-templates.html) (workshop source).
3. Type and creation method: the create page says only "Select a template type" (type names come from the overview page, §4); then `Global template` or `Start from scratch`; pick from `Global Template` (workshop shows a `Content Source` menu here).
4. Variables: select the Personalization Response Template, which is the content schema (workshop: `Default Response Template`). Global templates prefill variables (edit `Label`, `API Name`); from scratch use `Populate from Response Template` or `Add Variable`. Map each variable's `Default Value` to a schema attribute.
5. Code: edit HTML; insert variables with `Select variable…` → `Insert`. `Turn off auto-engagement tracking` stops view and click tracking, which is on by default.
6. `Save` stores progress; `Save & Activate` activates [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_template_create.htm&release=264.0.0&type=5). Activated templates become selectable in WPM [src](https://partnerworkshops.salesforce.com/workshops/salesforce-personalization/experience-templates.html) (workshop source); the mobile doc states "An active template appears in the template picker" [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_mobile_template_create.htm&release=264.0.0&type=5).

| Advanced variable option | Meaning ("primarily for building agentic experiences") |
| --- | --- |
| `Is Required` | Must have a value at runtime, from the default or a WPM override |
| `Is Overridable` | Default can be changed when configuring an experience in WPM |
| `Config Type` | `Schema Path` (schema attribute; recommended default) or `Static Value` (manual text, mainly for agent scripts) |
| `Delete` | Removes the variable |

- Source: [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_template_variable_options.htm&release=264.0.0&type=5).
- Workshop mappings. `Simple Hero Banner` with schema `Banner with CTA`: `BackgroundImageUrl` ← `Attributes > Image URL`, `CallToActionText` ← `Attributes > CTA`, `Header` ← `Attributes > Header`, `CallToActionUrl` ← `Attributes > CTA Destination URL`, `Subheader` ← `Attributes > Sub-Header`. `Simple Recommendations` with `Recs with Header`: `image`, `price`, `name`, `url` ← `Goods Product > …`. CSS goes in a `<style>` element in the same editor [src](https://partnerworkshops.salesforce.com/workshops/salesforce-personalization/experience-templates.html) (workshop source).
- Template filtering: in campaigns, the chosen content schema determines which templates appear [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_campaign_create.htm&release=264.0.0&type=5); mobile lists only templates matching the point's schema [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_mobile_create.htm&release=264.0.0&type=5). Whether WPM filters web templates by schema is UNVERIFIED.

### Template language, `subVar`, transformers
- Official docs say only "Handlebars" and link to handlebarsjs.com [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_template.htm&release=264.0.0&type=5); variables "can be referenced directly in the template HTML using Handlebars expressions" [src](https://partnerworkshops.salesforce.com/workshops/salesforce-personalization/experience-templates.html) (workshop source). No official SP page names the helper.
- Helper syntax (UNVERIFIED): `{{subVar 'x'}}` outputs a variable, `{{#each (subVar 'arr')}}` loops, `{{#if (subVar 'x')}}` renders conditionally [src](https://www.salesforce-personalization.guide/web-implementation/web-templates/) (third-party). App-built templates on 264 emit `{{subVar '<API Name>'}}`, and SDK logs report `transformerName` (Field-observed, undocumented).
- Connect REST (v66.0) exposes "Personalization Transformers": `/personalization/external-apps/transformer` (GET/PUT/DELETE, `idOrName`) and `/personalization/external-apps/transformers` (GET/POST; filters `source` = `{Global}`/`{Organization}`, `transformerType`, `transformerCategory`, `schemaReference`, `connectorNameOrId`, `channelType`, `isEnabled`) [src](https://developer.salesforce.com/docs/platform/connect-rest-api/references/connect-rest-api-personalization). Inference: experience templates are persisted as transformers, global versus org (UNVERIFIED).
- Legacy (pre-262) sitemap transformer format, useful when reading old sitemaps (UNVERIFIED) [src](https://www.salesforce-personalization.guide/web-implementation/web-templates/) (third-party):
```js
{ name: "<TEMPLATE_API_NAME>", transformerType: "Handlebars", lastModifiedDate: 0,
  substitutionDefinitions: { Header: { defaultValue: "[attributes].[Header]" },  // schema attribute
                             recs: { defaultValue: "[data]" }, name: { defaultValue: "[ssot__Name__c]" } },
  transformerTypeDetails: { html: `<h1>{{subVar 'Header'}}</h1>{{#each (subVar 'recs')}}<h2>{{subVar 'name'}}</h2>{{/each}}` } }
// registered via Personalization.Config.initialize({ additionalTransformers: [...] })
```
- The official `initialize` doc lists only `personalizationExperienceConfigs`, `customFlickerDefenseConfig`, and `customEngagementConfig`; `additionalTransformers` is UNVERIFIED [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/initialize-einstein-personalization-module.html).
- "Experience templates use HTML and CSS" [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_web.htm&release=264.0.0&type=5). JavaScript support, sanitization, and escaping are undocumented (UNVERIFIED).

## 9. Experimentation
- Tests personalized dynamic content, recommender-based content, or agent-based experiences on a personalization point [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_exp_web_experimentation.htm&release=264.0.0&type=5).
- Create: App Launcher → `Personalization Points` → point → Related tab → Experiment section → `New`. Permissions: `Personalization Points` and `Experiments` [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_exp_create.htm&release=264.0.0&type=5):
  1. Name, optional description (API name auto-generated).
  2. Primary metric (engagement signal metric that decides the winner). If a metric is missing, put its signal and metric DMOs and fields in the point's profile data graph.
  3. Optional secondary metrics.
  4. Optional targeting: `Always (No Conditions)`, `All Conditions Are Met`, `Any Condition Is Met`; resources `Direct Attributes`, `Related Attributes`, `Segments`, `Calculated Insights`, `Scheduling`, `Source`, `UTM Parameters`, `Visit Context`; `Add Condition` / `Add Groups` (groups combine conditions into more complex rules). Operators aren't listed ("Configure the operator, values, or dates"); don't reuse the engagement-signal filter operators. Max 50 targeting conditions per decision or experiment [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_basics_limits.htm&release=264.0.0&type=5).
  5. Optional control cohort (recommender or content), or `Defer response to the Personalization Decisions` so control traffic falls through to the point's decisions.
  6. Variation cohorts: percentage plus recommender or content; `Add Cohort`. Save → status `Created`.
- Rules [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_exp_considerations.htm&release=264.0.0&type=5):
  - Experiments inherit the point's profile data graph (filters available metrics) and response template (decides whether you test recommendations, content, or an agent).
  - Cohort assignment is sticky for the experiment's duration; an individual may be in several experiments at once.
  - Each cohort needs at least **1,000** participants; the first cohort is always the control.
  - Cohort sizes may differ but must total 100%; unallocated share goes to the control.
- Experiment Cohort DMO: `AllocationWeight__c` must total 100; `IsControl__c` allows one control cohort [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/experiment-cohort-dmo.html).
- Lifecycle, from the point's Related tab [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_exp_manage.htm&release=264.0.0&type=5):

| Action | Effect |
| --- | --- |
| `Start` | → `Started`. The row says a started experiment "can't be edited" |
| `Edit` | Any setting before start; after start, no functional settings, "including the API name" (contradicts the `Start` row) |
| `Stop` | → `Stopped`; afterward only `Archive` or `Delete` |
| `Archive` | Removes it from the point's Related tab so a new experiment can run; records and data kept in the Experiment tab |
| `Delete` | Removes the experiment and underlying records |

- Inference from the `Archive` wording: one active experiment per point at a time (UNVERIFIED).
- Analytics: results need up to 24 hours after start; the dashboard top has stop, edit, and delete controls. If data never appears, check that experimentation data lake objects are added and mapped in the data space [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_exp_analytics_status_and_controls.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_exp_analytics_troubleshooting.htm&release=264.0.0&type=5).
  - Primary-metric columns: `Cohorts`, `Personalizer`, the metric, `Lift`, `Credible Interval`, `Chance to beat control` (several cohorts can beat control), `Chance to beat all` (only one can). Secondary metrics show the same columns but "don't directly determine the experiment's winner" [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_exp_analytics_primary_metric_results.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_exp_analytics_secondary_metric_results.htm&release=264.0.0&type=5).
  - Statistics are Bayesian: the Summary DMO stores a "Bayesian credible interval", `ProbabilityToBeatControlPercent__c`, `ProbabilityToBeatAllPercent__c` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/experimentation-summary-dmo.html).
- Data Visualization tab (added week of August 17, 2026; 264): `Best Variation`, `Lift vs. Control`, `Probability to Beat Control`, `Probability to Beat All`, metric picker, `Performance by Variation` (95% credible interval, 50% HDI), `Daily Enrollment`. A range entirely right of the control baseline gets `Winner Found` ("Roll out this variation to all users"); otherwise `Inconclusive`. No automatic traffic reallocation is documented [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_exp_analytics_data_viz_tab.htm&release=264.0.0&type=5) [src](https://help.salesforce.com/s/articleView?id=release-notes.rn_personalization.htm&release=264.0.0&type=5).
- Primary metric eligibility: any engagement signal metric whose signal and metric DMOs and fields are in the point's profile data graph [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_exp_create.htm&release=264.0.0&type=5); `COUNT`, `SUM`, `AVG`, `DISTINCT` are supported in Experimentation, `SELECT` isn't (measurement-and-attribution.md §1.7). Rate metrics are analyzed: the Summary DMO's `ExperimentSummaryMetricType__c` can be `RATE` or `AVG`, with `SignalNumeratorValueNumber__c` / `SignalDenominatorValueNumber__c` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/experimentation-summary-dmo.html), and the primary-metric column "can report revenue or recommendation click-through rate" [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_exp_analytics_primary_metric_results.htm&release=264.0.0&type=5). Compound-as-primary is strongly implied, not stated.
- Participants per cohort: the Experiment Summary section gives "participant totals for the control cohort and all variant cohorts" (`Number of Individuals`) [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_exp_analytics_summary.htm&release=264.0.0&type=5); also `Daily Enrollment` and DMO field `AssignedParticipantsCount__c`. The 260 note says the Experiment Connect and Runtime Experiment Assignment APIs "Automate winner selection testing … without manual intervention" [src](https://help.salesforce.com/s/articleView?id=release-notes.rn_persnl_experimentation_api.htm&release=260&type=5). ## 11. Template authoring and placement practices
- Scope CSS: prefix every class, as the workshop's hero CSS does (`.sfdcep-banner`, `.sfdcep-banner-cta`, `.sfdcep-banner img`) [src](https://partnerworkshops.salesforce.com/workshops/salesforce-personalization/experience-templates.html) (workshop source). Never style bare tags or page classes; host CSS may reach your markup unless Shadow DOM isolation applies (UNVERIFIED, §4).
- Size to the container: that CSS uses `width: 100%` and a fixed `min-height: 600px`; tune or drop fixed heights. An empty target inside `display:flex; flex-direction:column` with non-stretch alignment rendered at 0 px width until `width:100%; align-self:stretch` was set on the template root (Field-observed, undocumented; standard flexbox behavior).
- Handle empty values: wrap optional fields in `{{#if (subVar 'x')}}…{{else}}…{{/if}}` and give `{{#each}}` loops a fallback (UNVERIFIED helpers, §4). Mark must-have variables `Is Required` [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_experience_template_variable_options.htm&release=264.0.0&type=5). Give merge fields default text; it replaces a missing value [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_point_decision_add_merge_fields.htm&release=264.0.0&type=5).
- Stable targets: use site-owned ids or `data-*` hooks, not generated classes; prefer sitemap content zones and `Current Page Type` over fragile element paths and URLs. On React, Vue, or Angular use a Content Zone Handler with `onRevert` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/integrate-personalization-modern-frontend-frameworks.html). Keep page-type `name` values and variable API names stable; they double as WPM bindings and Data 360 labels (§3).
- One placement path per point per page: either a sitemap zone with `Replace a Content Zone` or WPM element targeting, not both, to avoid duplicate renders and impressions. Audit with `Show All Personalization Experiences` [src](https://help.salesforce.com/s/articleView?id=mktg.persnl_wpm_use_predefined_templates.htm&release=264.0.0&type=5) and test back/forward-cache restores (§6).
- Engagement: keep auto-engagement tracking on unless you send events yourself with `personalizationId` / `personalizationContentId` [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/track-personalization-engagement.html). Pick `Product Engagement` for recommendations and `Website Engagement` for Dynamic Content.
- Safety: keep JavaScript in the sitemap or a Content Zone Handler (template JS is undocumented). Treat personalized URLs as untrusted; SP's mobile guidance says they "cross a trust boundary" [src](https://developer.salesforce.com/docs/marketing/einstein-personalization/guide/personalize-mobile-experiences-lowcode-reactnative.html).
- Save error `Please contact support — Unrecognized field "isMapped" at [line:1, column:512]` has no documentation; the wording suggests WPM client/server schema skew. Escalate to Support (Field-observed, undocumented).

## Gaps and uncertainties
- Doc-vs-doc contradictions:
  - WPM permission: "Web Personalization Manager user permission set" (access page) vs `Personalization Admin` / `Personalization User` (prerequisites, permissions topic).
  - Content-zone `selector`: optional (SP developer doc) vs required (MCP-breadcrumb migration pages).
  - Experiment `Start` row ("can't be edited") vs `Edit` row (only functional settings locked) on the same Manage page.
  - Experiment Connect API marked "Available in: v65.0", which the Marketing Cloud Next Handlebars reference ties to Winter '26 [src](https://developer.salesforce.com/docs/marketing/handlebars-for-marketing-cloud-next/references/mcn-handlebars-personalization-references/mcn-handlebars-reference-personalization-personalizationresult.html), while the release note lists it under February '26 (Spring '26 notes).
  - `cohortId` (parameter table) vs `cohordId` (body example); the `Related Attributes` description on the Create an Experiment page duplicates `Direct Attributes`.
  - Workshop is partly stale ("Feature Coming Soon", mobile templates "upcoming").
- Label drift: `Embedded Content` vs `Configure Embedded Content`; `Use Content Zone Handler` vs `Content Zone Handler`; `Page URL` vs `URL Address`, `Current Page Type` vs `Page Type`; `Select and Modify Existing Elements` vs `Select & Modify Existing Page Elements`; `New` vs `Add New`; `Agent Script` vs `AgentScript`; "response template" vs "content schema"; "Manual Content" (segment example) vs "Dynamic Content".
- UNVERIFIED: `subVar`, `substitutionDefinitions`, `additionalTransformers`; template JavaScript, sanitization, escaping; Shadow DOM rendering; transformer and experience-config storage mapping; WPM filtering templates by schema; one active experiment per point; precedence of overlapping experiences; Web Curation Agent = Adaptive Websites; whether web experiences list on the point record; campaign experience creation timing; the "element must be present" rule; web preview default individual.
- Field-observed, undocumented: `Current Page Type (<name>)` label; id-vs-class selector behavior and SDK `transformerName` log; `Delete` / `Cancel Preview` labels; `bfcacheAutoReinit`; the `isMapped` save error; the flexbox zero-width case.
